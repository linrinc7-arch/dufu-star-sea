# 05 · 把参考站的星系搬进《杜诗星海》

> 目标：不是「像照片一样真实」，而是「像他那片星空」。
> 依据：01-03 的逆向结论 + 04 的迁移经验；实现落在 web/index.html 的星系模块。

## 1. 参考站的星系公式（逆向所得，逐条可复现）

```js
// pretty/index.js:4749 —— 诗人 → 坐标，无坐标表
Y = { RADIUS: 3600, BRANCHES: 4, TWIST: 5.2, ARM_SPREAD: 0.42, THICKNESS: 0.11 }
r = FNV1a(id + name)                                  // 32 位
[lo, hi] = 420 + dynasty * 198.667                    // 朝代 → 半径带
o = mid + (a+b+c-1.5) * width * 1.5                   // 三角噪声散布
s = o / RADIUS
ang = arm(r%4) + s*TWIST + jitter ±0.19 + coreScatter // 4 臂 + 扭转
y   = (a+b+c-1.5) * o * 0.11 * 2.1 * bulge            // 盘厚 + 核球 ×1~3.6
```

配套三条视觉规律（:3880-3923、:13349-13358）：

1. **点数远大于可分辨像素**：193,000 点，97.2% 被压到 1.2 px，亮度靠叠加。
2. **颜色随半径走**：核暖 #fff1d6 → #fff7ec → 白 → 外圈冷 #cfe0ff，另有 4% 红巨星 #ff6d92。
3. **过曝 + bloom**：颜色 ×2.3 预过曝，Bloom{intensity:1.4, threshold:0.1}，并且关掉 tone mapping。

## 2. 映射到本作

| 参考站 | 本作 |
|---|---|
| 诗人 id + 姓名 | 诗题 + 编号 |
| 朝代 → 半径带（15 带） | 五期 → 半径带（5 带，越外越晚） |
| 每诗人一团诗星 | 每首诗一颗星 |
| 背景银河 193k 点 | 背景银河 80k 点 |
| 朝代色 | 五期色（PD_COLORS 暖→冷） |
| 名诗人 ×2.4 + 白 | 名篇 ×1.5 + 白热核心 |

## 3. 实现要点

### 3.1 布局（layoutStarGalaxy）
纯函数，一次算完 1,468 首；没有任何坐标文件。改了时期推定，星系自动重排。

### 3.2 背景银河（buildGalaxyBg + drawGalaxyPoints）
- 80,000 点用同一套臂生成；按半径分 5 段色 + 3.5% 红巨星；
- **计数排序分桶**：每个点落在「颜色 × 透明度」的 48 个桶里，画的时候一次 fillStyle 画一串，
  避免 8 万次状态切换（软件渲染下从 928ms 降到约 80ms）。

### 3.3 缓存
整层画进离屏 canvas：相机位移 < 0.9 px 不重画；大位移立即重建；小位移最多 900ms 一次。
自动缓慢旋转因此几乎不触发重建。

### 3.4 视角
右上角「天球 ›」在原星系视角与真实天球视角之间切换；两者共用同一批诗的两种坐标
（星系坐标 x/y/z 与天球方向 dir）。

## 4. 结果

- 对比图：迭代/截图/对比_参考站与本作星系.png
- 同机最坏情况（headless + SwiftShader）7~8 fps；命中缓存的帧只画 1,468 首诗星。
- 与参考站的差距：80k vs 193k 点（Canvas 2D 的 draw call 成本）；本作更锐，参考站更糊——
  这恰好是 GPU 点云与 CPU 光栅的差别，不必强行追平。

## 5. 还能再近一步的三件事

1. **每首诗一个 Fibonacci 小球**：参考站每位诗人的诗星团 Yr=min(3000,35+13√n)，面积 ∝ 诗数；
   我们 1,468 首若按体裁拆成 8 个球，会立刻有「团」的层次。
2. **赠诗边**：5,051 条三次贝塞尔 + 沿线脉冲（参考站 :5601-5660）；本作有 12 位交游诗人，可直接用。
3. **两层视差自转**：背景 0.012 rad/s、前景 0.019 rad/s。
