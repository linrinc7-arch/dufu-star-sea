## A. 相机与自由飞行

### A.0 先说结论（三句话）

1. **相机是手写的**：全包 `OrbitControls` / `TrackballControls` **0 命中**，由 `Es()`（【S:7179-7790】，612 行）一个组件完成"输入层 + 五模式状态机 + 每帧解算"。【R03:504-506】
2. **只有一种"缓动"**：`1 - k^dt` 的指数平滑；没有 tween 库、没有动画时长、没有关键帧。【R03:551-553】
3. **"飞行"由三条互相独立的分支组成**：① 自由飞（WASD，桌面默认）；② 锁定/奔赴（点星、深链、搜索）；③ 电影弧线（认领流星）。每帧只走一条，靠 `return` 切换。【S:7579-7786】【R03:532-541】

### A.1 相机矩阵怎么算（Es()）

| 环节 | 做法 | 证据 |
|---|---|---|
| 角度状态 | 一个持久 `Euler(0,0,0,'YXZ')`（useRef），**YXZ 顺序**：先偏航(y)→俯仰(x)→滚转(z) | 【S:7182】a.current = new M(0,0,0,'YXZ') |
| 矩阵 | **不手写 Matrix4**。只维护 camera.position 与 camera.quaternion，投影矩阵由 three 内部算 | 【S:7397,7655,7724】（只写 quaternion/position） |
| 轨道解算 | 球坐标：`pos = target + (sinYaw·cosPitch, sinPitch, cosYaw·cosPitch) × dist`，然后 `lookAt(target)` | 【S:7641-7649】 |
| 朝向阻尼 | lookAt 得目标四元数 → `camera.quaternion.slerp(target, 1-0.0025^dt)` | 【S:7652-7655】 |
| 滚转 | 在 slerp **之后**再左乘"相机局部 Z 轴"的旋转：`q.multiply(setFromAxisAngle((0,0,1), roll))` | 【S:7654,7675,7723】 |
| 自由飞 | 直接改 Euler 的 x/y（拖拽）+ z（Q/E 累积角），每帧 `quaternion.setFromEuler`；位置单独积分 | 【S:7728-7736,7752,7786】 |
| 位置与朝向分离 | 位置 `lerp`、四元数 `slerp`，**两条时间常数可以不同**（电影镜头 0.0015 vs 0.0025 → 先位移后转向，产生"甩镜"） | 【S:7592-7597】 |

**三种"看的方向"是分开存的**，这是全节最值得抄的结构：

~~~text
d.current  { yaw, pitch, dist }   // 轨道模式：绕 target 的球坐标（锁定诗人/总览）
a.current  Euler(YXZ)             // 自由飞：相机自己的姿态（含 roll）
h.current  { orbitYaw, orbitPitch, zoomLog,   // 外部（手势/拖拽）注入的"待积分"增量
             lookYaw, lookPitch }              // 用 1-exp(-dt/0.055) 衰减后并入 d 或 a
~~~

> **复算说明**：【R03:546-548】把 0.0025 / 0.0015 的「每 60 fps 走完」写作 11% / 17%；按它自己的公式 `1-k^dt`（dt=1/60）复算应为 **9.5% / 10.3%** —— **公式无误，百分比偏大**，落地以复算值为准。

- **帧率无关**：`1-k^dt` 在 30/60/120 fps 下手感一致（这是选它而不是 `lerp(a,b,0.1)` 的唯一理由）。【R03:551】
- **可被打断**：任何输入都直接改目标值，下帧继续收敛，不需要 cancelAnimationFrame。【R03:553】
- 所有路径都把 dt 夹到 **0.05 s**（`Math.min(n,0.05)`），切后台回来不瞬移。【S:7567,7772,7784】【R03:375】

### A.8 落地到 Canvas 2D（把上面翻译成 ctx）

参考站的 900 是**硬编码焦距**，等价于 `focal = 900`（单位与场景一致）。Canvas 里应改成与视口绑定：

~~~js
const focal = (H / 2) / Math.tan(fovY / 2);        // fovY = 55° → focal ≈ 0.9603·H
// 欧拉 YXZ（roll=0）导出的相机基（与 three 完全一致）
const cy=Math.cos(yaw), sy=Math.sin(yaw), cp=Math.cos(pitch), sp=Math.sin(pitch);
const right = [ cy, 0, -sy];
const up    = [ sy*sp, cp, cy*sp];
const back  = [ sy*cp, -sp, cy*cp];      // 指向相机后方；前方 = -back
// 世界 → 相机
const vx = x-camX, vy = y-camY, vz = z-camZ;
const xc = vx*right[0]+vy*right[1]+vz*right[2];
const yc = vx*up[0]   +vy*up[1]   +vz*up[2];
const zc = vx*back[0] +vy*back[1] +vz*back[2];   // >0 = 在身前
if (zc <= near) skip;                              // near = 0.1 当量
const sx = CX + xc/zc*focal, sy2 = CY - yc/zc*focal;
const px = clamp(size * focal / zc, 1.2, 70);      // 与参考站同式，只把 900 换成 focal
~~~

- 每帧：`yaw += (targetYaw-yaw)*(1-k^dt)`，同理 pitch；再按上式投影。
- 位置积分：`pos += forward * 140 * speed * min(dt,0.05)`，**forward 用 -back**，斜向必须先归一化。
- 焦距必须随 H 变，否则 4K/竖屏上点径比例全错（【R03:1068】已点名这个坑）。

### B.4 加色叠加与"不需要排序"

- 全部 7 层：`transparent:true, depthWrite:false, blending:2`（AdditiveBlending）。【R03:276】
- **lighter 满足交换律 → 不需要按 z 排序**，这是最省的一条优化。【R03:1072】
- 片元里的 alpha 是"亮度"而不是"透明度"：`gl_FragColor = vec4(color*a, a)`（预乘）。【S:3951-3955】

### B.5 泛光（Bloom）与色调映射

~~~jsx
{quality === 'high' && <EffectComposer><Bloom
  intensity={1.4} luminanceThreshold={0.1} luminanceSmoothing={0.28}
  radius={0.85} mipmapBlur />}
</EffectComposer>}
~~~

【S:13349-13358】【R03:460-475】

| 参数 | 值 | 为什么要这么设 |
|---|---|---|
| intensity | **1.4** | 加色叠加后整体提亮，不压暗星点 |
| luminanceThreshold | **0.1** | 极低 → **几乎所有星点都参与泛光**；正因为低，才需要把颜色先 ×2.3 预过曝 |
| luminanceSmoothing | 0.28 | 阈值软过渡 |
| radius | 0.85 | mipmap 链模糊半径 |
| mipmapBlur | true | 比双 pass 高斯便宜（postprocessing 的 mipmap 链） |
| toneMapping | 挂 Composer 时置 **0（NoToneMapping）**，卸载恢复 ACES(4) | 允许过曝到纯白；低画质走 ACES |

【S:3014-3022】【R03:476-485】
**低画质不挂 Bloom**（`n === 'high' && ...`），DPR 也压到 1.5。【S:13349】【R01:605-606】

### B.6 背景银河怎么分层

1. **主体点云**：同一 On() 里三组点（12 万主体 / 9 千"装饰星" / 6.4 万补充），共 193,000；low 档 42k+3.5k+24k = 69,500。【S:3849-3853】【R03:104】
2. **远景星壳**：5,200 点、球半径 7,200、`PointsMaterial size=16`，**唯一受雾影响**的层。【S:3970】
3. **中心星云**：1 张程序化 Sprite（128² canvas 径向渐变，`An()` 【S:4022-4038】），`scale=1.05×RADIUS`、opacity 0.24。【S:3959-3969】
4. **雾**：`fog #03040a, 2400 → 13000`，把 7,200 处的星壳融掉约 45%。【S:13339】【R03:487】
5. **背景色**：`#03040a`（与 fog 同色，边界不可见）。【S:13338】

> 参考站**没有 fbm 星云贴图**——"云"是 19 万点加色累积 + 1 张 Sprite + Bloom 的结果。【R03:1131】

### C.7 提示文案的写法（可直接套用的 6 条规则）

1. **HUD 一行说明书**：全句用 · 分隔的动宾短语，关键词包 b（金色）：`WASD 飞行 · 拖拽转向 · Q/E 滚转 · 滚轮调速 · F 全屏 · **点诗星**看其真作 · **点虚空**从噪声里捞诗`。【S:7923-7928】；b 样式 `color:var(--gold); font-weight:600`【CSS:.hint b】
2. **数值口径必须自解释**：不写"速度 1.0"，而写 `速度 ×1.00 · 140 单位/秒`（倍率 + 物理量），且用 tabular-nums 防跳动。【S:7930-7939】【CSS:.speed】
3. **引导三步 = 三句短语 + 一句世界观**：标题 2–6 字（诗云 · 一切可能的诗 / 点星 · 点虚空 / 飞出去），正文一句 20–35 字（点星，读他的诗；点星与星之间的黑，捞一首这个世界上还没有过的诗。）。【S:10256-10272】
4. **最后一步是"动作门"不是"下一步"**：卡片只写 `按住 W，飞出去。` + 副行 `A/S/D 平移 · 拖动转视角`，**真的按 W 才关掉**（keydown w/W/ArrowUp → i()）。【S:10302-10311,10381-10389】；移动端换成 `拖一下星空，出发。` + `双指捏合，拉近拉远。`【S:10363-10370】
5. **首次揭示用"断言 + 破折号解释"**：`**这首诗此前并不存在** —— 它是你点下的那一刻，从那个坐标当场算出来的。同一个点，永远捞出同一首。`【S:8137-8138】
6. **title 属性写"功能 = 具体数值"**：`画质：高=16万粒子+辉光；低=更少粒子、关闭辉光（弱显卡更流畅）`、`更多：指引 / 行星 / 赠诗 / 引力 / 关于 / 反馈`。【S:7895,7889】按钮文字带快捷键：`隐藏界面 · H`。【S:7913】

> 语气总结：**短句、动词开头、不解释原理、把"世界观"放在正文第二句**；数字一律给单位；不用感叹号。

### D.2 建议的落地顺序（每条都能独立验收）
