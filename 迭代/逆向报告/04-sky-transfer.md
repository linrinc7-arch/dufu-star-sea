# 04 · 把参考站的"星空"搬进《杜诗星海》：诊断、改法与结果

> 参考制品：<https://shiyun.cohenjikan.com>（sha256 见 03-render-ui.md §0.1）
> 本文是"学习"的落地部分：**不是复刻那个页面，而是把它关于"星空为什么好看"的机制，
> 移植到一部纯 Canvas 2D、单文件、断网可跑的作业里**。
> 前面的 01/02/03 是逆向报告（构建 / 数据 / 渲染），本文只讲一件事：改了什么、为什么。

---

## 0. 结论先行

旧版的天幕有三处硬伤，都是"投影/密度/尺度"层面的，不是配色层面的：

1. **1,468 首诗用轨道相机投影**（`project()`，`cam.dist=2.9`），而诗的半径是 1。
   于是整片"星海"只落在屏幕中央约 914×914 px 的圆盘里，圆盘边缘因视线切向而**堆积成环**——
   这就是"只是随机分布的球状尘埃"的来源。参考站的星是铺满全视野的。
2. **天幕是 512×256 的 fbm 烘成的 2048×1024 全景贴图**，缩放到约 5372 px 宽，
   任何一次放大都会把 1 颗星拉成一片棉花；上下黑边来自 pitch 钳位后贴图覆盖不到。
3. **亮度靠尺寸，不靠叠加**：几千颗星各画各的，没有"大量 1 px 点重叠 → 累积成大光"的机制，
   也没有真实星等/色温，所以天空没有层次。

改完之后：**人在球心**（gnomonic 投影铺满全视野）、**银河来自真实等照度轮廓**、
**52,000 颗背景星 + 5,044 颗真实恒星是向量点云而不是贴图**、
**1,468 首诗按真实银道带分布**、星有星等长尾与色温、天球层做了缓存。
同一台机器上（headless + SwiftShader，最坏情况）帧率 6.4 → 15.4 fps。

## 1. 参考站里真正支撑"星空感"的七个机制（证据）

每条都指到 `pretty/index.js`（prettier 后的行号，见 03-render-ui.md §0.1）。

| # | 机制 | 数字/写法 | 证据 |
|---|---|---|---|
| 1 | **点云，不是贴图** | 背景银河 high 档 **193,000** 个加色点（120,000+9,000+64,000）；整站零星云贴图 | `:3847-3970` |
| 2 | **绝大多数点被压到 1.2 px** | `gl_PointSize=clamp(aSize*900/-z, 1.2, 70)`；实测 **97.2%** 的点被 clamp 到 1.2 px | `:4887-4890`；03 §8 |
| 3 | **靠叠加出亮度** | 同屏最近邻中位 **1.9 px** → 大量点重叠，加色(blending:2)累积成光 | 03 §8 实测 |
| 4 | **亮度 18 倍长尾** | `aSize 2.49 → 49.44`；诗人星 `(1.4+clusterSize*0.32)×(名诗人2.4)` | `:4833-4834` |
| 5 | **颜色即语义** | 朝代色；47 位名诗人 `lerp(白,0.22)×1.8` —— 名诗人天然更白更亮 | `:4858-4863` |
| 6 | **过曝 + bloom** | 颜色先 `×2.3`"预过曝"，再 `BloomEffect{intensity:1.4, threshold:0.1, smoothing:0.28, radius:0.85, mipmapBlur}`，且挂 Composer 时把 `toneMapping` 置 0 | `:4897`、`:13349-13358`、`:3014-3022` |
| 7 | **结构来自哈希，不来自噪声图** | `FNV-1a(id+name)` → 朝代半径带 `[420+198.667·id, +198.667]` → 4 臂 `2π/4 + r/3600·5.2` → 盘厚 11%、核球 ×3.6；三角噪声 `a+b+c-1.5` | `:3284`、`:3785-3793`、`:4749-4798` |

两条"看不见但很关键"的：

- **两层视差自转**：背景银河 0.012 rad/s、诗人星 0.019 rad/s，阻尼一律 `1-k^dt`（k=0.0025/0.0015，τ≈0.16 s）。
  星空因此"有深度"，而不是一张图在转。
- **看不清的星不可点**（`uGate=4.4·dpr`）：先按颜色 ID 离屏渲染，再回读 `(2R+1)²` 小窗；
  被 `uGate` 判为"小于可见阈值"的星根本不进拾取缓冲 —— 于是"虚空"真的可点。

## 2. 旧版《杜诗星海》的三个硬伤（照着机制逐条对）

| 参考机制 | 旧版现状 | 后果 |
|---|---|---|
| 星铺满视野 | `project()` 把半径 1 的球放在 `cam.dist=2.9` 的轨道相机前，fov 1.55 → 整片星海只占中央 ~914 px | 像"一团球状尘埃"，四周是空的黑 |
| 点云叠出光 | 星是 `drawImage(64px 精灵)`，尺寸 3~48 px 各画各的 | 星与星之间没有累积，没有"银河" |
| 真实结构 | 银道带用随手写的极点 `N={0.42,0.66,0.62}` | 与任何真实天球都对不上 |
| 放大仍清晰 | 天幕是 2048×1024 贴图，拉到 5372 px | 一放大就是棉花 + 黑边 |
| 星等长尾/色温 | 全站一颗星一个颜色、一个尺寸档 | 没有层次 |
| 过曝 + bloom | `applyBloom(0.07)` 直接模糊整帧再叠 | 只能提亮，不能"抓"亮部 |

## 3. 改法：从"画一张星云"改成"建立一个天球"

### 3.1 人在球心（最重要的一处）

```js
// web/index.html · render()
p._q = (viewMode==='sky') ? projectSky(p) : project(p);
```

`projectSky` 本来就是写好的 gnomonic 投影（`sx=CX+(x/z)*f`，`f=min(W,H)*0.95*zoom`），
只是**从来没被调用过**。切换之后诗的视角从"围着球看"变成"站在球心看"，
1,468 颗星自然铺满整片天，边缘那圈"环"消失了。
选中诗人时的镜头也改成按方向角飞：

```js
fly={yaw:Math.atan2(d.x,d.z), pitch:Math.asin(d.y), zoom:...};
```

### 3.2 真实天球数据 `web/sky_data.js`（121 KB，构建期生成）

来源 d3-celestial（HYG 星表派生，CC-BY-SA），`work/rea/shiyun/stars/build_sky_data.py` 压缩：

| 数据 | 规模 | 格式 |
|---|---|---|
| 恒星 | **5,044 颗**（mag ≤ 6） | `ra*10, dec*10, mag*100, bv*100`，CSV |
| 银河等照度轮廓 | 5 级、173 个环、**2,375 点**（原 30,676 点，Douglas-Peucker 0.28°） | `[lon*10, lat*10]` |
| 星座连线 | 88 星座、150 条折线、893 顶点 | `[[lon*10,lat*10],…]` |

星等 → 尺寸/透明度的长尾：

```js
sz[i]=0.7+3.1*Math.max(0,(5.9-m)/4.5);      // 亮星到大，暗星 1 px
a   =0.24+0.62*Math.max(0,(6.4-m)/5.0);      // 星等 → 亮度
```

色温来自 B-V 色指数，7 档（`#9eb6ff → #ffc08a`）——这正是参考站"颜色让星群有层次"的做法，
只不过人家用朝代色，我们用真实色温 + 诗的分类色。

### 3.3 银河：真实轮廓 + 噪声切暗带 + 向量星

- 轮廓按 5 级等照度填进 1536×768 的等距圆柱画布，轻微模糊（1/2 降采样往返一次）；
- 逐像素上色：**银心方向（RA 266.4°, Dec −28.94°）一侧暖金，外圈冷蓝**，
  两层噪声切暗带（大尺度尘埃）+ 两层高频噪声做卷须（`nFbm(lon*14, lat*22)`）；
- 气体最后放大到 4096×2048 存成 `SKY_TEX`；**星不烘进贴图**。

### 3.4 52,000 颗背景星 = 向量点云（贴图只留气体）

```js
while(placed<52000){                     // 按气体亮度加权采样
  pp = 0.085 + 0.915*Math.pow(gi/255, 0.80);
  if(Math.random()>pp) continue;
  ...                                   // 方向向量 + 亮度 0.05~0.67 + 冷/暖
}
```

每帧投影、`fillRect` 1 px、加色。**任何缩放都清晰**——这是贴图做不到的，
也是之前"放大就是棉花"的直接解法。

### 3.5 天球层缓存（性能）

星星是静的，只有相机在动。于是把"气体 + 背景星 + 星座线 + 真实恒星"整层
画进一张与屏幕同尺寸的离屏 canvas，**相机位移小于 0.35 px 就只做一次 `drawImage`**：

```js
var fresh=(!k)||k.zoom!==cam.zoom||
          Math.abs(k.yaw-cam.yaw)*f>0.35||Math.abs(k.pitch-cam.pitch)*f>0.35;
```

自动缓慢旋转（0.000045 rad/帧 ≈ 0.038 px）不再每帧重画整层，约每 9 帧才重建一次。

### 3.6 诗的分布：贴着真实银道带

旧的 `bandBasis()` 用的是随手写的极点；换成**真实银河北极（RA 192.859°, Dec +27.128°）**，
并且把带的基向量 `B1` 取成"银心方向在银道面内的投影"，于是 `phi=0` 就是银心，
`layoutGalaxyPoems()` 里原来的 `cos(phi-1.15)` 变成 `cos(phi)`——
**诗自然地向银心收拢**，和气体、背景星用同一套天球坐标，三者不再各说各话。

### 3.7 亮度：学"过曝 + bloom"，但用 Canvas 2D 的做法

- 诗星着色改成"彩色外晕 + 白热核心"两层：核心永远过曝到白（真实恒星的读法），
  外晕保留意象/时期的颜色语义；
- 尺寸改成 `(2.7+3.1*mag*magMul)`，上限 20 px，`×(0.85+0.30*zoom)`；
- `applyBloom` 从 `0.07` 提到 `0.125`，并在降采样时加 `blur(6px) brightness(1.12)`，
  接近参考站 `threshold 0.1` 那种"几乎全部星点都参与泛光"的行为。

## 4. 结果

| 指标 | 旧 | 新 |
|---|---|---|
| 星空投影 | 轨道相机（球在中央，半径 914 px） | 球心 gnomonic，铺满全视野 |
| 银河 | 512×256 fbm 贴图（无真实形状） | 5 级真实等照度轮廓 + 尘埃暗带 + 卷须 |
| 背景星 | 9,000 个 64px 精灵 | **52,000 个 1 px 向量点** + 5,044 颗真实恒星 |
| 星色 | 每颗一色 | 真实 B-V 色温 7 档 + 白热核心 |
| 放大 1.5× 以上 | 棉花 + 黑边 | 星始终 1 px 清晰，气体保持柔软（本该柔软） |
| 天球层开销 | 每帧全量重画 | 缓存，0.35 px 阈值 |
| 帧率（headless/SwiftShader 最坏情况） | 6.4 fps | **15.4 fps** |

对比图：`迭代/截图/对比_旧新天幕.png`（左旧右新，同机位同尺寸）。

## 5. 还没做的三件事（下一轮）

1. **诗的"星团"结构**：参考站每位诗人是一个 Fibonacci 球（`Yr=min(3000,35+13√n)`），
   我们 1,468 首还是散点；按体裁/时期做成 4~6 个"星座球"会立刻有层次。
2. **视差自转**：参考站背景 0.012 rad/s、前景 0.019 rad/s 的两层错速；
   我们现在只有单层 `autoSpin`，可以拆成两层。
3. **地面**：参考站在虚空里没有地面；我们的"巡游"模式还有一条渐变地平线，
   可以改成山脊剪影 + 雾（`drawGround` 已经是独立函数，改动面很小）。
