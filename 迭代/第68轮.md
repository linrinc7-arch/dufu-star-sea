# 第 68 轮 · 2026-10-21 03:00 · 长诗的「卷轴」实验与回退

## 试了一次，失败了

交互评审说「长诗全屏三栏，第一句分别是第 1 / 68 / 135 句，读序断裂」。
我想的解法是把它做成**卷轴**：竖排右起、每句一列、横向滚动——那才是中文长诗原本的读法。

实现之后它是坏的：`writing-mode:vertical-rl` + `height:calc(100vh-210px)` 让 200 列同时铺开，
压到右栏解析上，整屏糊成一片字。**没有把握的东西不该留在交付里**，所以回退了。

## 回退后的状态

长诗整屏是**三栏 + 栏间细线**（`column-rule`），标题跨栏。
读序仍是「先读第一栏到底、再读第二栏」，但有分隔线后至少看得出是同一首诗的连续排版，
而不是三首并排的诗。

这是「可接受的次优解」，不是理想解。理想解需要重写整屏的左栏渲染（按页切分而非 CSS 分栏），
那是一个独立的工程，不适合在没验证的情况下塞进交付。

## 这一轮真正落地的

### 声音（R8 的三条）
- 钟的音阶改成 G A B D E，与磬同宫（原来 G C D F G，F 撞 E 是小二度）
- 钟分音 0.09/0.035/0.014 → 0.14/0.055/0.022（+3.8dB，压回底噪之上）
- 空气层增益 0.03 → **0.12**、带通 1400 → **2400Hz**（评审说「挪了位置没开灯」）
- 五类界面音归一：hover ×2.45、type ×2.0、zoom ×0.36（原来跨 27.5dB）
- 导航悬停、切章、图例开合三类动作接上音
- 记忆恢复改成 `ctx.resume().then()`，只有真 running 才写「开」

### 版式
- 手机长诗正文被 `.long` 的 23px 覆盖 → 15px 兜底（11.9 屏 → 约 8.6 屏）
- 手机图例 64px 只看得到 5/10 → 150px 可滚

## 教训

「读序」这种问题不能靠 CSS 属性硬拧。竖向排版要改的是**渲染方式**（分页），不是 writing-mode。
