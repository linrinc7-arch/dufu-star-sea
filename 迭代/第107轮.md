# 第107轮：一动就变暗的真凶——拖拽抽稀（2026-10-21）

## 用户说的

> 可是我只要有一点点移动，画面瞬间变暗。

## 真凶

轨道拖拽时缓存重建会按 `big`（本帧转动折合的像素）抽稀背景星：

```js
var stride = roamOn ? 2 : ((big>18) ? 3 : 1);
```

`big = |Δyaw| · f0`，f0≈1351px，灵敏度 0.0026 → **鼠标动 7px 就 big>18 → 背景星抽成 1/3**，
于是「一动就暗」。更糟的是补帧规则只认 `stride===3`：

```js
(kk.stride===3 && big<0.5 && now-kk.t>180)   // 抽稀到 2 时永远补不回来
```

## 改法

1. 轨道里**不再抽稀**：只有甩得很快（`big>600`，约一帧 230px）才降到 1/2，同时补 1.45 倍亮度
2. 补帧规则改成 `kk.stride>1`（任何抽稀档停下 180ms 后都补回全量）
3. 半分辨率时也补 1.25 倍亮度

## 验收（同一机位，2550×1351）

| 状态 | stride | 整帧亮度 | p99 |
|---|---|---|---|
| 静止 | 1 | 14.19 | 194 |
| 拖 6px | 1 | **14.17** | 194 |
| 快拖 300px | 1 | **14.17** | 196 |
| 松手 | 1 | 14.19 | 196 |

改前：拖 6px 亮度会掉到 ~9.5（抽稀 1/3）。现在全程 14.17~14.19，肉眼无变化。

## 说明

上一轮说的“几何位移”只解释了大角度转动时的缓慢变化；**“瞬间变暗”是抽稀**，这一轮才真正解决。
