# 第99轮：繁星（2026-10-21）

## 用户说的

> 星空看着好空啊，我想做那种繁星的效果，让杜甫这位诗人的诗给用户极大的震撼。

## 诊断

上一轮把点调亮调大，但**点的数量**没变（8.6 万）。真正的『繁星』不是把已有的点放大，
而是要有几十万颗暗到只当颗粒的星铺底——可现在没有。

为什么以前不做：`fillRect` 在软件光栅下一颗星约 0.75µs，38 万颗要 280ms，建缓存时整屏卡死。
本轮用 `ImageData` 直接写像素绕开这条路：同样的 40 万颗实测 **6.6ms**（Node 微基准），
再加 1.4ms 的 `fill()` 打底。

## 做法

| 层 | 内容 | 成本 |
|---|---|---|
| 繁星底（新） | 31 万颗盘内尘埃（alpha 13~70/255）+ 25 万颗深空星（alpha 16~62） | 每帧重建约 10~14ms |
| 可数的星 | 9.6 万颗盘内点 + 3.8 万颗远景壳，仍走 `fillRect`（有颜色、有体量、有长尾） | 与上一轮同量级 |
| 亮星长尾 | 上限 2.7px→4.0px；双倍体量的概率 0.2%→0.4% | 0 |
| 机位 | 默认 `cam.dist` 3.9→**2.95**（星海占满画面），出生动画同步到 2.95 | 0 |

尘埃层走 `putImageData` 直接铺在星系缓存的第一层（顺带把夜色也铺了），失败时自动退回纯色底。
半分辨率飞行时尘埃抽样一半，保证遨游不掉帧。

## 验收

| 项 | 结果 |
|---|---|
| 点数 | 134,000 可数星 + 560,000 尘埃星 |
| 重建（软件光栅 2529×1238） | 可数层 90ms + 尘埃 12ms（同机旧基线：86,000 点 65ms） |
| 1600×900 截图 | 盘面到边缘都是星，四角有深空星 |
| 2560 宽截图 | 盘面颗粒可数，四角仍有星 |
| 出生 | 0.72 → 2.95，闪白在 2.4s |
| 冒烟 | SMOKE ok card=true 登高 |
| 报错 | 0 |

证据：迭代/截图/R99_星海_总览.png、R99_星海_2560宽.png、R99_出生_睁眼.png
