## 三条问题（现在仍然最伤）

### 1. 三层色的第三层连续第三轮缺席，而蓝色已经和图例「日月」焊死

- **赭金 0.8%。** 新代码 `wG = Math.min(1, Math.pow(dust,1.2)*2.2) * Math.min(1, dens*3.2)`：两个 `min` 互相掐——尘埃重的地方密度本来就低，`dens*3.2` 把金按死在暗带里。实测色相 20–50° 只占 **0.69–0.8%**，比 R3 的 0.5% 只多 0.3。R3 给的目标是 **8–12%**。
- **洋红 16.8%，没动。** `wM` 的窗口还是 `(dens-0.52)/0.20`，乘子 `fil*2.4` 让脊线**两侧**都上粉，于是洋红成了场上饱和度最高、面积第三大的东西，却仍然不代表任何语义。
- **蓝现在就是「日月」。** 源的青蓝是 (30,140,212)=203.8°，经 `1-exp(-c/255*L*2.2)` 的逐通道压缩后落到 **215.3°**（p25–p75 = 212.3–222.4），图例「日月」是 **208.9°**。差 6.4°，σ 内完全重合。按 ±10° 把十个图例色投到画面上：

  | 图例 | 色相 | 画面占比 |
  |---|---|---|
  | 日月 | 208.9° | **45.5%** |
  | 释道 | 215.4° | **54.3%**（就是背景本身） |
  | 亲友 | 320.9° | 6.7% |
  | 愁思 | 275.4° | 5.0% |
  | 病老 / 兵戈 / 鸟兽 / 江山 / 器物 / 草木 | 0–172° | **0.08–1.3%** |

  十色里六色的存在感低于 1.5%，剩下四色（日月/释道/亲友/愁思）吃掉几乎全部着色像素——其中两色恰好是底色。十色里只有四色 >2%。图例还在，对照物没了——这不是「颜色不够多」，是**颜色不承载信息**。

**改法与验收**

```js
// buildNebulaTex()，:980–988 一带
var wG = Math.pow(dust, 1.15) * 0.95;              // 去掉 dens 乘子：金只跟尘埃走
var wM = Math.exp(-Math.pow((dens-0.52)/0.145,2)) * Math.min(1, fil*1.7);  // 收窗口、只留一侧
var wB = Math.max(0, 1 - wM - wG);
var cr=(wB*24 + wM*198 + wG*226)/sum;              // 蓝往青里再推一步
var cg=(wB*146 + wM*52 + wG*150)/sum;
var cb=(wB*204 + wM*118 + wG*78)/sum;
```

```js
// drawNebula() 之后补一层金尘：低频 dust × 赭金，screen 0.12
ctx.globalCompositeOperation='lighter'; ctx.globalAlpha=.12;
ctx.drawImage(GOLDTEX, ...);   // GOLDTEX = 用 NEB.map 的 96×48 低频图调出来的赭金贴图
```

**验收**（同一 hue 直方图脚本）：蓝 **60–70%**、洋红 **8–12%**、赭金 **8–12%**；蓝的最终像素色相落在 **196–202°**，与「日月」208.9° 拉开 **≥8°**；「日月±10°」的覆盖率从 **45.5% 降到 <25%**；十色里至少 6 色 >2%（现在只有 4 色）。

### 3. 所有字号都是固定值，没有一处按容器算：标题断名、1366 裁字、长诗卡空成一片

三个症状，同一个根：**字不随容器走**。

- **标题 66px 固定，断在专名里。** 用 `Range` 逐字取行：
  - 1920：`秋日夔府咏怀奉寄郑` / `监李宾客一百韵` —— 把「郑监」劈开；
  - 1366：`秋日夔府咏怀` / `奉寄郑监李宾` / `客一百韵` —— **3 行、h=297px、y 106–403，占屏高 39%**，正文第一行被推到 y=470（61% 处）。
  - 根因：标题只有 **690px** 可用（它在 `1fr` 的左栏里），66px × 15 字 × 1.14 ≈ 1128px，必然折；而折点由浏览器按字数均分，不看词。
- **1366 的诗卡把末字切了 13.1px。** 诗区 **419×152.8**，`scrollHeight 180` vs `clientHeight 153`，`.col` 底边 **510.2**，页脚顶边 **497.1** → **13.1px 被页脚盖掉**（`c_card_clip_1366.png` 里「回 / 哀」下半截没了）。`--poem-fs` 的 `15.5px` 断点根本没生效：`fitPoem()`（:2392）每次 `el.style.setProperty('--poem-fs', FS+'px')`，FS=17.5（:2364），行内值压过媒体查询；`#card .col{font-size:17.5px}`（:448）又直接写死一层。
- **1920 的长诗卡反过来空。** 诗区 **629px 高**，`.col` 只有 **128px（20.4%）**，上下各 250px 黑；`fitPoem()` 里算完 `need / avail / needW / availW` 四行（:2395–2402）就扔掉了，注释写着「一律先落在侧边栏」。

**改法**（一个函数收三处）

```js
var FS_STEPS=[11,12.5,15,17.5];                 // 只用 8 档里的正文段
function fitPoem(p){
  var el=document.getElementById('c-poem'); if(!el||!p) return;
  var maxLen=Math.max.apply(null, p.L.map(function(s){return s.length;}));
  var boxH=el.clientHeight-52, boxW=el.clientWidth-60;
  var f=Math.min(17.5, (boxH-34)/(maxLen*2.05), (boxW-60)/(p.L.length*1.16+16));
  var pick=FS_STEPS[0];
  for(var i=0;i<FS_STEPS.length;i++) if(FS_STEPS[i]<=f) pick=FS_STEPS[i];
  el.style.setProperty('--poem-fs', pick+'px');   // 把行内值从 "FS" 改成 "算出来的档"
}
```

```css
#card .col{font-size:var(--poem-fs,17.5px)}       /* 删掉 :448 的直写 17.5 */
#card .poem{align-items:flex-start;padding-top:0}/* 长诗别在 629 高的盒里居中成一条 */
#c-full .fs-t{grid-column:1/-1;text-wrap:balance;word-break:keep-all}
.nb{white-space:nowrap}                           /* 郑监 / 李宾客 这类专名包起来 */
```

**验收**：1366《登高》`scrollHeight ≤ clientHeight`（现在 180 > 153），末字完整落在页脚线以上 ≥8px；长诗卡诗区填充率从 **20.4% 提到 ≥45%**；标题在 1920/1366 都 **≤2 行**、**不跨「郑监」「李宾客」**、1366 高度 ≤220px（现在 297）。

## 一句总评

这一轮把「星被天幕吃掉」这件事真正修掉了——压暗做在密度曲线上而不是叠一层黑，所以气氛退下去、星星没陪葬，星:地 6.45 → 9.43 是四轮里最干净的一次光影改动。但作者性仍然只落在两色气氛上：**赭金 0.8%，蓝色已经和图例「日月」焊成一色（45.5% 的着色像素落在它 ±10° 内）**，十色图例在画面上找不到六个对照物；全屏读诗页依旧是 94% 的黑，还多了一行指向自己的提示；而 66px 的标题在 1366 上断了三行、把「李宾客」劈成「李宾/客」。**这一轮涨的是「星能不能看见」，没涨的是「看见的是不是杜甫」——+2，65。**
