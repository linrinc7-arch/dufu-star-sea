### 2. 长诗阅读：卡里 1366 要 19.4 屏；全屏三栏是“三个开头同屏”；390 的 clamp 被 `.long` 盖掉

三件事其实是一件事：**这轮把“版面”做得更像阅读页了，但阅读顺序和字号还没有。**

**（a）卡里：12 屏只在 1920 成立。** 全图版 1366 的卡高 768：配图 150 + 卡头 194 + 页脚 228，诗窗只剩 **196px**；100 行 × (25.8 + 12) = 3,804 → **19.4 屏**。单文件版因为没有长诗配图，诗窗 358px → **10.6 屏**。同一份代码，配图在不在差 8.8 屏。说明“长诗卡”的预算仍然被配图和依据栏吃掉，而不是被“两句一行”吃掉。

**（b）全屏：多栏在同一个滚动容器里，顺序是断的。** 1920 三栏的 `first` 分别是 **0 / 67 / 134**，三栏顶都在 **y=198.1**；也就是你第一眼看到的是第 1、68、135 句并排。要顺序读完，只能先往下滚 3 屏读第 1 栏，再滚回顶部读第 2 栏，再回顶读第 3 栏。1366 两栏更狠：第一栏 101 句，`sh 4,652 / h 742 = 6.27 屏`，读完一栏要回顶一次。**④ 的 2 栏让每栏变宽、7 字行不挤了，这是对的；但它把每栏拉长到 6.3 屏，阅读代价更大。**

**（c）390 的正文没有吃到 clamp。** 实测 390 长诗全屏：`#c-full` 9,743px / 818 = **11.91 屏**，`fs-ln` **23px / 43.7px**。只把 `.long` 那条覆盖改成 `inherit`，同一页变 **7,006px / 818 = 8.56 屏、15px / 30px**（反事实已做，下图）。这 3.35 屏是这一轮声称要省、但没省下来的。

**（d）390 的右栏在正文后 9,012px。** 单栏把 `fs-right` 排到 200 行之后：写作时间 / 写作地点 / 诗中之意 / 机器同题都在 9,012px 处，用户读完诗基本不会看到。桌面是 sticky，手机不是。

### 3. 图例：手机上点开只铺开一半；开关状态会不同步；滤镜状态关掉就看不见（②）

- **手机裁掉一半**：390 点「图例」后 `#legend` 高 63px，`scrollHeight 113`，`overflow:hidden`；十类里只完整显示 **5 类**（日月/江山/草木/鸟兽/器物），病老/愁思/兵戈/亲友/释道在 838–882px，**超出 832px 的裁切线，且没有滚动条**。也就是说：手机上点开图例，等于只给了一半答案。
- **开关状态不同步**：先点开图例，再把「着色」从意象切到时期——`renderLegend()` 里 `lg.classList.add('collapsed')` 把图例收起，但 `#lgtog` 的 `.on` 没被清掉，**按钮仍是金色“开”态、面板已经关了**。实测 `legend display:none / class=collapsed / lgtogOn=true`。
- **滤镜状态关掉就看不见**：点「日月」→ `#qc` 变成金色的「219」；再收起图例，页面上只剩右上角一个没有主语的数字。`#legend` 里那个 `.sel` 还在，但被 `display:none` 藏住了；`#phl` 也没动。用户无法知道 219 是“日月”还是某次检索。
- **键盘/读屏不可达**：`#lgtog` 是 `SPAN`，`tabIndex=-1`，没有 `aria-expanded / aria-controls`；五个 `.sb` 也是 `DIV tabIndex=-1`。新加的两个控件都只能用鼠标。
- **语义代价**：颜色是这片天幕唯一的“语法”；图例一收，第一屏就没有“这颗星为什么是金色”的解释。按钮在，但“图例”是元语言，不是答案。

## 另外五条（次伤，但别过夜）

**A. 卡内 68 字长题还是吃掉半张卡。** 390：9 行 / 300.1px / 卡头 408px = **48.4%**，诗区被压到下半张；根因是 `#card .tt` 的 `padding-right:110px` 还在（`web/index.html:221`），文字可用宽只有 217px。把两个按钮挪到标题上方一行、标题 `padding-right:0`，同题预计 6 行 / 180px（估算），卡头降到约 21%。验收：390 长题卡头 ≤30%、标题与「声音/全屏」按钮 `overlap=0`。

**B. 「共 200 行」现在又说错了。** 两句一行后是 **100 行**，提示条还写「共 200 行」（`web/index.html:2204`）；而且这条 28px 的「点这里整屏读」是全卡唯一通往阅读页的桥，命中高度只有 28px。一行改法：`'共 '+p.L.length+' 句 · '+Math.ceil(p.L.length/2)+' 行 · 点这里整屏读 ›'`，`#c-poemhint{min-height:40px;display:flex;align-items:center}`。

**C. 对比度三笔老账。** `POEMS / 712—770` 仍 **2.29–2.48:1**（`#meta-r .num{color:#55524a}`，`web/index.html:66`）→ 改 `#8a8578` 即 4.9；1920 的操作提示 `#hint` 是 **2.73:1**（基础色 `#6f6b61`），反而比 1366 的 4.24 更暗——把媒体查询里的 `#8f8a7e` 提到基础规则；搜索占位在暗底 5.3:1，但在 390 的亮星云斑上取样可掉到 **3.0:1**，因为输入框没有底衬，建议给 `#search` 一层 `background:rgba(4,5,10,.55)` 的 8px 晕。

**D. 键盘/读屏仍是零。** `:focus-visible` 0 条、`aria-live` 0 条、`inert` 0 处、`prefers-reduced-motion` 0 条；卡片关着时 `#c-poem`（`overflow:auto`）还在 Tab 序列里。最低限度：卡关时 `#card{inert}`、`#qc{aria-live="polite"}`、`#lgtog` 与 `.sb` 可聚焦、reduce 下停自动旋转和逐字入场。

**E. 手机第二排：重叠修了，语义丢了。** 「诗云/生涯/声音」三个 label 在 ≤700 被 `display:none`（`web/index.html:517`），于是最右只剩一个孤零零的「关」——它看起来像关闭，不像声音开关；同时「着色/意象/时期」高 28px，「伪诗/巡游/关」高 34–36px，四个盒子的顶边差 4px，第二排是参差的。建议保留「声音」label，把 `.ctrlrow` 改成 `overflow-x:auto;flex-wrap:nowrap`（第 7 轮就提过），让整排能横滑；盒子统一 `min-height:36px`。

**为什么是 −2**：这轮把“安静”做出来了，代价是“认得出来”被拿走了。① 让桌面 4/5 的章节从“读得到”变成“猜得到”，手机上直接没有；② 让图例在手机上只铺开一半，而且开关状态会撒谎。这两笔是新增的，直接扣在可发现性和状态反馈上。另一边，③ 的长诗卡确实从 16.7 屏降到 7.1（单文件同口径），68 字长题从 1,720px 修回 335px，⑤ 的标题 clamp 全对，⑥ 的声音 3/3 无异常——这些都记了分，但抵消不了入口的损失。

## 一句总评

这版最像“作品”的一屏仍然是长诗全屏：34px 的题、三栏排开、右边写作时间，远远看过去像一页摊开的杜诗；最像“产品”的一步是长诗卡的两句一行，200 行从 16.7 屏压到 7.1（单文件同口径）。但**这轮把导航和图例都改成了“要先知道才找得到”的东西**：四个章节是 1.44:1 的编号，手机上没有章节；图例点开只有一半；长诗全屏三个开头同屏。下一步别再加“安静”，先把入口还回去，再把读页捋成一条线。
