## 分页这一轮做到了什么（给结论，不只给感觉）

**页内是真正的一页，不是“三个开头”。** 第 1 页三栏各 6 行：

    栏1  绝塞乌蛮北 / 孤城白帝边 / 飘零仍百里 / 消渴已三年 / 雄剑鸣开匣 / 群书满系船
    栏2  乱离心不展 / 衰谢日萧然 / 筋力妻孥问 / 菁华岁月迁 / 登临多物色 / 陶冶赖诗篇
    栏3  峡束沧江起 / 岩排石树圆 / 拂云霾楚气 / 朝海蹴吴天 / 煮井为盐速 / 烧畬度地偏

把 18 行按“列 x 再 y”排序得到的顺序是 `0,1,2,…,17`，与 DOM 完全一致——也就是说，**读法回到“一栏到底、再下一栏”**，翻页后第 2 页首句是 `有时惊叠嶂`（第 19 句），第 12 页是 `金蓖空刮眼 / 镜象未离铨`。200 / 18 = 11 余 2，共 12 页，页数正确；18 行 = 9 联，**页的边界落在联的边界上**（对联不跨页），这一点比“按屏切”讲究。

**但栏的边界不总是落在联上。** 1366 是两栏，18 / 2 = 9 行/栏（奇数），第 1 栏结束在 `筋力妻孥问`、第 2 栏开始于 `菁华岁月迁`——同一联被拆到两栏。1920 的 3×6 是偶数，没有这个问题。**验收：所有栏高为偶数行。** 最小改法是按栏数反推每页行数：两栏时用 16 或 20 句/页，而不是固定 18。

### 2. 分页条还不是一个控件：键盘 0、边界不说话、末页会跳

四个问题其实是一个控件的四个面：

**（a）键盘到不了。** 阅读态连按 14 次 Tab，焦点序列是 `INPUT#q → SPAN#autog → DIV#csound → BODY` 循环；`#c-full` 内可聚焦元素 **0**，分页条两个 `SPAN` 是 `tabIndex=-1`、无 `role`、无 `aria-label`，页码 `1 / 12` 无 `aria-live`。而方向键在阅读态仍然转天幕：按一次 `ArrowRight`，相机 yaw 从 **−2.1031 → −2.0431**，页码仍是 1/12——**键盘用户唯一的“翻页”是把背后的星空转一下**。更糟的是 Tab 会落进透明页脚上的「声音 关」（`body.reading #foot{opacity:0;pointer-events:none}`，但没 `inert`），焦点跑到看不见的地方。

**（b）边界不说话。** 第 1 页点「‹」、第 12 页点「›」，都**静默无反应**；两个箭头没有 `disabled`、没有变灰，和可用状态长得一模一样（唯一区别是鼠标悬停时变金——那恰好会让“到头了”看起来像“可以点”）。

**（c）末页会搬走。** 第 12 页只剩两行，`#c-full` 的 `align-content:safe center` 把整块往上收，分页条 y 从 **554.3 → 335.9（1920，Δ218）**、**646 → 296.5（1366，Δ350）**、**735.8 → 279.8（390，Δ456）**。连点 11 次的手，到第 12 次要去够一个已经跑掉 218–456px 的目标；同时这一页看上去像“空页”。

**（d）页码没有事件语义。** 翻页只换 `innerHTML`，页号变化没有任何可读的播报；视觉上也没有过渡（60ms 抓帧已经是新页），反馈只剩一声 `audCue('filter')` 和数字本身。

**改法（半小时，已做反事实）**

    <!-- 分页条从 .fs-left 里拿出来，作为 #c-full 的兄弟：sticky 在多栏 column-span 子元素里不生效 -->
    <div id="fsbar"></div>

    #card.reading #fsbar{display:flex;position:absolute;left:0;right:0;bottom:0;z-index:6;
      justify-content:center;align-items:center;gap:22px;padding:12px 0 16px;
      background:linear-gradient(to top,#06070c 55%,rgba(6,7,12,0))}
    #c-full{padding-bottom:84px}                 /* 别让条压住最后一行 */
    #fsbar .pgb{min-width:44px;min-height:44px;display:inline-flex;align-items:center;
      justify-content:center;font-size:15px;border:1px solid rgba(236,231,219,.18);border-radius:2px}
    #fsbar .pgb[aria-disabled="true"]{opacity:.24;border-color:rgba(236,231,219,.10);pointer-events:none}
    #fsbar .pgc{min-width:64px;text-align:center;font-variant-numeric:tabular-nums}

JS 里 `renderFull()` 之后同步：`role=button`、`tabindex=0`、`aria-disabled`、`aria-live=polite`；`keydown` 在 `readingOn` 时接管 ←/→/PgUp/PgDn 并 `preventDefault()`；读完一页别让方向键再去转天幕。

**反事实实测**：44×44 + 边界置灰 + 键盘接管后，`‹` 在第 1 页 `aria-disabled=true / opacity .22`，`ArrowRight` 把 `2 / 12` 翻到 `3 / 12`（见下图）。**注意**：我试过 `position:sticky` 和给 `.fs-left` 加 `min-height` 两种“留在原位”的办法，都没稳住（sticky 在 `column-span:all` 子元素里不生效；min-height 后末页条仍从 526 掉到 307），所以推荐把条移出多栏容器或 `position:fixed`；固定条在 390 滚到底时仍停在 768–844（下图）。

**验收**：Tab 能到 `‹ / ›` 并按 Enter 翻页；第 1 页 `‹` 与第 12 页 `›` 可见置灰且不可点；分页条在 1→12 页之间 y 漂移 ≤8px；命中 ≥44×44；390 滚到页底时条仍在屏内。

### 3. 门槛 60：264 首诗留在旧版式；手机翻页条会滚出视口

**（a）分页只覆盖 18 首。** 1,468 首里 **>60 句只有 18 首**；**19–60 句有 264 首**（19–24：125 / 25–40：100 / 41–60：39），它们一条都不分页。≥1700px 时 `.fs-left.mid{column-count:2}`（`:280`）照旧。实测 52 句的《送李校书二十六韵》1920：**两栏 27 + 25 行，`scrollHeight 1,375 / clientHeight 1,054`**，第 2 栏从第 28 句开始——读者读完第 1 栏要滚回顶部读第 2 栏，**上一轮被判“读序断裂”的那个结构，在这一段长度里原封不动**。61 句的《八哀诗 赠司空王公思礼》就正常分页（1/4）。也就是说，同一屏里，62 句是页，59 句还是“版面”。

![52 句《送李校书二十六韵》1920：两栏 27+25，第 2 栏首句是第 28 句；不分页，要滚回去](r09/ux/r9_51_full_mid_1920.png)

**（b）手机翻页条会离开视口。** 390 上整页 `scrollHeight 1,575 / 818`，最大滚动 **757px**，而分页条在 **735.8px**——往下读右栏（写作时间 / 诗中之意 / 机器同题）超过 23px，条就出屏；读完再想翻页，必须先把页面滚回顶部。每页都这样，12 页就是 12 次“滚回去找按钮”。

**改法**

    /* 1) 按容量分页，别再按 60：能读成一页的才不翻页 */
    var PER = 18;                                  // 或按可用高度算，取偶数（见 §读序）
    var _paged = p.L.length > PER;                 // 原：> 60
    var _total = _paged ? Math.ceil(p.L.length/PER) : 1;
    // 两栏时把每页行数改成偶数（16 / 20），别让栏边界切断一联

    /* 2) 手机的分页条 fixed（与第 2 条同一份 #fsbar） */
    @media (max-width:700px){ #c-full{padding-bottom:96px} #fsbar{bottom:0} }

**验收**：52 句的诗在全屏是 3 页、无滚动；390 滚到右栏底部时仍能直接点“›”；任意一首 19 句以上的诗，页内都不出现“第 1 句和第 N 句并排却要求你先往下滚”。

## 另外六条（次伤，但别过夜）

**A. 末页 2 行不是错，但两件事要一起做。** 200 = 11×18 + 2，书里也有短末页；问题在“短末页 + 分页条上跳”同时发生。把条固定（§2）之后，短末页可以保留；若还想更稳，按 12 页均分成 16–18 行（偶数）即可，不必强求 18。

**B. 长诗卡还是全站最长的滚动，而通往页面的桥只有 28px。** 卡里 100 行：1920 `4,200/366 = 11.5 屏`、1366 `3,804/196 = 19.4 屏`、390 `3,804/449 = 8.5 屏`（与上轮同）；提示条 `#c-poemhint` 高 **28px**、`padding:0 34px 12px`，是卡里唯一通往分页的桥。同一张卡上 meta 写“200 句”、提示条写“**共 200 行**”（`web/index.html:2226`）——同一个面板自相矛盾，因为卡把两句并一行，实际是 100 行。改：文案 `'共 '+p.L.length+' 句 · '+Math.ceil(p.L.length/2)+' 行 · 点这里整屏读 ›'`，并把「整屏读」做成卡头常驻的 44px 按钮（和「全屏」并排），别只留一行字。

**C. 图例按钮仍在撒谎（复测）。** 点开图例 → 把“着色”从意象切到时期：`#legend` 变成 `display:none`、`class=collapsed`，而 `#lgtog` 仍是 `s on`（金色开态）。根因还在 `renderLegend()` 第一行 `lg.classList.add('collapsed')`（`:2359`），只收面板不同步按钮。一行修：先记 `_open`，最后 `_lt.classList.toggle('on', _open); _lt.setAttribute('aria-expanded', String(_open))`。

**D. 页码记忆有两套行为。** 同一首关掉再开，落在上次那页（实测 5/12）；中间点开过别的诗再回来，归零。两套都对，但用户无从预期。建议：从卡片进全屏一律回第 1 页；只有“阅读中途按 Esc 再进”才续读，并在页码旁给一个“续读”小字。

**E. 滚动时文字从「声音 / 退出」底下穿过。** 1366 阅读页仍可滚 148px，390 每页 1.92 屏；滚下去时诗行/右栏文字会滑到右上角两个按钮下面（r9_26 顶部“烧畬度地偏”与“声音 关/退出”重叠），那一条没有 scrim 也没有渐隐。给 `#card.reading` 头部一条 `background:linear-gradient(#06070c 60%,transparent)` 的 64px 遮罩即可；顺带把 `#c-full` 的滚动条在阅读态收细。

**F. 键盘/读屏仍是零。** 源码 `:focus-visible` **0** 条、`prefers-reduced-motion` **0** 条、`aria-live` **0** 条，`aria-*` 总共 5 个（4 个 `aria-checked` + 1 个 `aria-label`，都在声音开关上）。最低限度：卡关时 `#card{inert}`、`#qc{aria-live="polite"}`、`#lgtog / .sb / .pgb` 可聚焦、reduce 下停自动旋转与逐字入场。

## 评分拆解

| 维度 | 上轮 | 本轮 | 说明 |
| --- | ---: | ---: | --- |
| 可发现性 / 信息架构（25） | 16 | **18** | 手机章节从 0 个回到 5 个可点（+1）；分页条给了明确的“还有下一页”（+1）；首屏 0 诗题、手机无提示、编号 2.46:1 仍按上轮口径扣分，不重复加扣 |
| 核心交互可靠性（25） | 20 | **20** | 12 页鼠标/触摸都通，翻页归零滚动，0 异常；但键盘 0、边界静默、末页搬走，新控件只覆盖一半输入方式 |
| 状态反馈（20） | 17 | **17** | 页码常显、声音标签与 ctx 一致（+1）；边界不置灰、末页跳动 218–456px、图例按钮仍不同步（−1） |
| 长文本阅读（20） | 18 | **19** | 读序根治（>60 句）、手机 15px、每页一屏（+2）；19–60 句仍分栏滚动、1366 栏断联、长诗卡 19.4 屏没动（−1） |

| **合计** | **78** | **82** | **+4** |

**为什么是 +4**：这轮做的是一件对的事，而且做对了——**把“读序”从 CSS 属性问题变成渲染问题**，18 句一页、按列读、页间单调，这是这个作品从“版面”变成“书”的一步；手机端同一首从 11.9 屏压到每页一屏，是九轮里对手机阅读最大的一次改善。扣分不在功能，在“控件完成度”：分页条是鼠标的，边界不说话，末页会跑；以及门槛 60 让它只修了 18 首、把 264 首留在原地。

## 一句总评

**这轮最像“书”的一屏，是长诗全屏第 2 页**：标题还在，三栏各六行，栏间一条细线，页脚一行“2 / 12”，读完一栏接着读下一栏，翻过去第一句就是“有时惊叠嶂”。**最不像“产品”的一处，是它的翻页按钮**：键盘够不着，到头了不吭声，最后一页还会自己挪走半屏。下一步别再加“效果”，把分页条做成一个真正的控件，再把 19–60 句那 264 首也接进同一套页。
