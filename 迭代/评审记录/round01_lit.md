## 最伤的三个问题（每条带证据）

### 1. `analysis.js` 少一个逗号，42 条人工解析在交付版里一条都不执行

证据链是闭合的：

- `web/analysis.js:36` 的 `"江南逢李龟年"` 对象以 `}` 收尾，下一行直接是 `"梦李白二首 一"`，**缺一个逗号**。用 `new Function()` 解析，报 `Unexpected string`。
- 浏览器实测：`Uncaught SyntaxError: Unexpected string @...:554`，`window.ANALYSIS` 为 `false`、0 个键；`analysisFor()` 于是走 `web/index.html:2035-2044` 的 fallback。
- 全屏实拍（`shot_03_full_denggao.png`）右栏因此变成：**写作时间"推定：流寓湖湘 · 766—770"、写作地点"行迹不详"、诗中之意"以「浊酒、酒杯、落木」为主要意象……归入「器物」一类"**；而 `analysis.js` 里《登高》写的是"767 年秋（大历二年）/夔州"。正确的那一段被语法错误吞掉了，错的那一段被端上桌。
- 同一首诗的卡（`shot_02_card_denggao.png`）元信息是"七言律诗 · 56字 · 8句 · **器物** · **≈流寓湖湘 推定**"。"流寓湖湘"用于 767 年夔州已经不对，"器物"更把一首悲秋诗归到了酒器类。

更刺眼的是，这段 fallback 自己承认"这不是考据，是统计"，却被放在"诗中之意"的标题下。对《登高》这样的诗，"酒杯"甚至不是词——原句是"潦倒新停浊酒杯"，"浊酒"加"杯"；"酒杯"是跨词切出来的伪意象。**一个 2.9% 覆盖率的解析层，被一个字符的语法错误降到了 0%。**

### 2. 名篇正文错字与错配：文本层不可信，且没有校记

这不是一两处异文，是一串形近误字，且都落在最常被引用的句子上：

- 《旅夜书怀》"官因老病休" → **"官应老病休"**
- 《阁夜》"野哭几家闻战伐" → **"千家"**；"人事依依漫寂寥" → **"音书"**
- 《咏怀古迹五首 三》"环佩空归月夜魂" → **"夜月魂"**
- 《江南逢李龟年》"歧王宅里寻常见" → **"岐王"**
- 《月夜忆舍弟》"寄书长不避" → **"不达"**
- 《江汉》"秋风病欲疏" → **"欲苏"**
- 《梦李白二首 一》"魂来枫叶青" → **"枫林青"**
- 《画鹰》首字缺（"㧐身"只剩"身"），"俱目似愁胡" → **"侧目"**
- 《茅屋为秋风所破歌》"茅飞度江" → **"渡江"**；"归来倚仗" → **"倚杖"**；"床床屋漏" → **"床头"**
- 《石壕吏》"一男附书致" → **"附书至"**；"出入无完帬" → **"完裙"**
- 《客至》"盘餐市远无兼味" → **"盘飧"**
- 《同诸公登慈恩寺塔》"高标跨苍天" → **"苍穹"**；"日宴昆仑丘" → **"日晏"**

最直观的是《绝句》卡（`shot_05_card_jueju.png`）：标题《绝句》、"名篇"，正文是"江边踏青罢 / 回首见旌旗 / 风起春城暮 / 高楼鼓角悲"，题解却引"**窗含西岭千秋雪，门泊东吴万里船**"。那两句属于《绝句四首 三》（"两个黄鹂鸣翠柳"），是另一首诗；真正的"两个黄鹂"在数据里题作"绝句四首 三"（#933），没有名篇标记，也没有配图。名篇卡把两首诗缝在了一起。

同类的键名错配还有：《丽人行》在数据里题作"**杂曲歌辞** 丽人行"，`ANALYSIS["丽人行"]` 与 `art["丽人行"]` 永不命中；《羌村三首》被拆成"羌村 一/二/三"，解析键也永不命中。42 条解析里至少 2 条是死键、1 条挂错诗、2 组同名诗共用一条。

### 3. 系年与题材标签把统计噪声当事实，且用"推定"包装

把逗号补上后做静态比对，**42 条解析中有 23 条的 `pd` 与解析自己写的年份冲突**（按 731—745 / 746—755 / 756—759 / 760—765 / 766—770 五期折算）：

- 《春望》757 春、长安 → 卡上"**≈流寓湖湘 766—770**"（`shot_04_card_chunwang.png`）
- 《茅屋为秋风所破歌》761 成都 → "**陷贼与为官 756—759**"
- 《客至》761 春 → "**困守长安 746—755**"
- 《闻官军收河南河北》763 春 → "**流寓湖湘 766—770**"
- 《江南逢李龟年》约 770 → "**漂泊西南 760—765**"

更麻烦的是"五期"本身把 766—767 的夔州和 768—770 的湖湘并成一期，取名"流寓湖湘"。于是《登高》《秋兴八首》都被盖上"湖湘"的章，而它们写在夔州。生平时序里 **766 条写"秋作《秋兴八首》《登高》"，767 条反而只写《壮游》《昔游》《缚鸡行》**；五期说明也写"作《秋兴八首》《登高》（766）"，只有被吞掉的 `analysis.js` 写着"767 年秋"。同一部作品，两个年份。

题材标签同理：`p.d` 是"十类意象词典"里命中最多的一类，不是主题。《登高》= 器物（因为"浊酒/酒杯"），《春望》= 病老（因为"白头/泪"），《兵车行》= 宗教哲理。读者看到的是"这首诗属于这一类"，实际只是"这类词在这首诗里出现得最多"。这个差别，卡片上没有说清。

另外两处小但扎眼：

- **算法演示自己拆自己的台**（`shot_07_algo.png`）：榜单第 3 名是《春望》，页脚却写"这一屏里没有一首是你想读的"。《春望》恰是人人想读的那一首；这个反讽不是设计出来的，是文案没有对过输出。
- **出处声明与正文矛盾**：About 面板一处写"天幕不是照片，也不是贴图：那一片银河，是九万首机器写的诗"（`web/index.html:2196`），页脚却保留"天幕照片：ESO / S. Brunier 全天银河全景（eso0932a），CC BY 4.0"（`:2218`）。代码里没有加载这张图，这条版权声明是旧的、无主的。

还有可读性：`.evd` 9.5px `#57544c`、`.mt` 10.5px `#6a675e`、`.fs-v.small` 11.5px `#6f6b61`，在 1920 屏上要凑近看。**注释再准，看不见等于没有。**

## 三条改法（每条具体到怎么改）

### 改法 1：先让解析活过来，再让空态说人话（JS + 构建 + 文案）

1. **补逗号**：`web/analysis.js:36` 行末加 `,`。
2. **构建期加语法闸**：`pipeline/04_bundle.py` 第 13 行读入 `analysis` 之后、第 31 行替换之前，加：
   ```python
   import subprocess, tempfile
   with tempfile.NamedTemporaryFile('w', suffix='.js', delete=False, encoding='utf-8') as f:
       f.write(analysis); tmp = f.name
   subprocess.run(['node', '--check', tmp], check=True)   # 语法不过就不许打包
   ```
   再加一条 headless 冒烟测试：打开单文件，注入 `window.onerror`，断言 `typeof window.ANALYSIS==='object' && Object.keys(window.ANALYSIS).length>=42`。这次事故就是没有这道闸。
3. **空态别装成解析**：`analysisFor()`（`web/index.html:2035`）的 fallback 改成
   ```js
   return {y:'系年待考', w:'—', m:'本首暂无人工释义。', s:'缺'};
   ```
   在 `renderFull()` 里，`a.s==='缺'` 时只保留"写作时间/地点"，另起一块标题叫"**统计特征（不构成释义）**"，把原来的统计句挪进去；"诗中之意"四个字只留给人工解析。卡片上加一枚"解析待补"的小标签。
4. **把注释调到能读**：`.evd{font-size:10.5px;color:#7e7a6e}`、`.mt{font-size:11px;color:#8a8578}`、`.fs-v.small{font-size:12.5px;color:#8a8578}`。这三处是注释的"最后一厘米"。

### 改法 2：做一张可审计的校勘表（数据 + UI）

1. 新建 `data/collation.csv`，字段 `id,line,base,corrected,source,note`；以中华书局《杜甫全集校注》或仇兆鳌《杜诗详注》为底本，先把 **42 首人工解析 + 30 幅配图对应的诗**逐字校一遍。首轮就收上面列出的 13 组，另加《兵车行》"边亭/边庭""阑道/拦道"、《自京赴奉先》"白手/白首"。
2. 在 `03_export_web.py`（或 `10_export_data.py`）写 `data.js` 之前套用修正表；有实质异文的行，给 `p` 加 `collation:[{line, base, variant, source}]`。
3. 卡片和全屏的诗歌下方加一行小字：
   > 底本《全唐诗》；参校仇兆鳌《杜诗详注》。"官应老病休"一作"官因"，今从仇本。
   没有异文的诗，也至少标一句"底本《全唐诗》，未经校勘"。这就是"注释分寸"：**宁可承认没校，不要假装校过。**
4. **修《绝句》的错配**：把 `hot`、`art`、`ANALYSIS` 从"绝句"移到"绝句四首 三"（#933）；#836 若要保留，就单独写"江边踏青罢"的题解，别再引"窗含西岭"。《丽人行》把题名归一为"丽人行"，或改用 id 键；《羌村三首》同理。

### 改法 3：以诗 id 为键，重做系年与标签的呈现（JS + 数据 + 文案）

1. **键改 id**：`ANALYSIS`/`ART` 从"标题"改成 `p.i`（字符串），`analysisFor(p)` 改成 `ANALYSIS[p.i] || ANALYSIS[p.t]`。这一刀同时解决《望岳》三首、《赠李白》两首、《绝句》、《丽人行》、《羌村三首》的全部错配。
2. **系年标注降级**：`02b_periods.py` 加一张 `MANUAL` 表，把 42 首有系年的诗按 id 钉死；其余诗在卡上把"≈流寓湖湘 推定"改成"**≈语义近邻（非系年）**"，tooltip 写"由意象近邻推断，不作系年依据"。有 `ANALYSIS[p.i]` 的诗，直接不显示这个 chip，改显示解析里的年份。
3. **修可见的年份**：生平时序 766 条删去《登高》，767 条补上；五期说明改成"作《秋兴八首》（766）、《登高》（767）"；《登岳阳楼》在 768 冬（解析）与 769（时序）之间择一，并注明"系年有异说"。
4. **把方法说出来**：METHOD 面板加一段"系年怎么推的"：五期关键词表、语义近邻补全、42 首人工系年上的准确率/错误率，最后写"只作浏览线索，不作考据"。现在 METHOD 只讲 TF-IDF/t-SNE/KMeans，不讲那张决定每张卡标签的系年模型——读者无法审计，这比算错更伤。
5. **文案对齐输出**：算法演示页脚改成"《登高》排第 28 名；但同一屏第 3 名是《春望》——算法能算密度，算不出这两首哪个更好"。这比"没有一首是你想读的"诚实，也更有说服力。

## 一句总评

星海造得很好，诗还没有站稳：一个逗号让 42 段解析全部沉默，十余处名篇错字让"教材"二字立不住——先把文本校成可引用的本子，再让星图发光。
