## 三、还剩的三条最伤

### 1. 长诗卡：一句一行 + 20px 空档，200 句变成 16.7–25.6 屏

横排本身是对的方向，但排版把它做成了「目录」：

| 视口 | 诗区 | scrollHeight | 屏数 | 每屏行数 | 行 pitch | 句宽 / 卡宽 |
|---|---|---|---|---|---|---|
| 1920 | 451×595 | 9,958 | 16.74 | 12 | **49.7**（29.7 + 20） | 79.5 / 441 |
| 1366 | 419×358 | 9,162 | **25.59** | 8 | 45.7（29.7 + 16） | 79.5 / 419 |
| 390 | 373×607 | 9,163 | 15.1 | 13 | 45.7 | 79.5 / 373 |

- 20px 空档不是设计出来的：`#card .poem{gap:16px}`（302 行）在 `.horiz` 的 column flex 里仍然生效，再加 `.col{margin-bottom:4px}`（258 行），把 1.98 的行高撑成了 **3.3 倍字号的 pitch**。视觉上每句都像独立条目，偶句和出句被拆开，读不成一联。
- 五言句只有 79.5px，右侧 360px 空着；200 句纵向 9,958px。1366 诗区只有 358px 高，**每屏 8 句、要滚 25.6 屏**，比竖排时代更难建立「整首诗」的形状。
- 提示文案仍是「共 200 列 · 点这里整屏读 ›」，单位错了；没有「第 41 / 200 句」的进度感。

![长诗卡 1920：每屏 12 句，句与句之间 20px；五言句 79.5px，卡宽 441，右边整片是空的](r7_type/F03_card_long_1920.png)

**改法**

1. **对句成行**：`render` 时把 `L[2i]` 与 `L[2i+1]` 放进同一 `.col`，中间 `1.2em` 间距；200 句 → 100 行，1366 从 25.6 屏降到约 12.8 屏，1920 从 16.7 降到 8.4 屏。这是最省事、最像「诗」的一刀。
2. **把 flex gap 归零**：`.horiz{gap:0}`、`.horiz .col{margin-bottom:0}`；行高 1.75、字号 16px；联与联之间用 6–8px 的段落距。仅这一步 1920 就会从 9,958 降到约 6,740（10.3 屏），1.98 才真的是行距。
3. **超过 120 句改为「首屏 12 句 + 渐隐 + 整屏读」**，不要在 358px 里塞 25 屏；或至少加「第 n / 200 句」的 sticky 进度。
4. 文案：`共 200 列` → `共 200 句 · 约 13 屏`；滚动条箭头（2× 带里是 Windows 原生金色三角）建议 `::-webkit-scrollbar-button{display:none}` 或换成 overlay thumb。

### 2. 1366 长诗全屏：三栏各 134px，五言贴边、十言撞栏

1366 的 `#c-full .fs-left.long` 仍是 `column-count:3`（275 行），栏宽 `(489−88)/3 = 134`；而长诗的字号是 23px / 1.9（276 行），**不吃** 282 行的 `clamp(15px,…,23px)`。

- 五言：`5 × 23 × 1.16 = 133.4`，与 134 的栏宽只剩 **0.6px** 侧白；三栏看起来像三条贴边的窄带，句与句没有呼吸。
- 七言：`7 × 26.68 = 186.8`，靠 44px 栏距硬吃，左右各溢 26px；`八哀诗 赠秘书监江夏李公邕`（86 句）实测 `maxTW 153`，已经越过栏边。
- 十言：数据里有 5 首把两句五言并成一句（「世传闾丘笔峻极逾昆仑」「豺遘哀登楚麟伤泣象尼」……），`10 × 26.68 = 266.8`，左右各溢 66px；栏距只有 44px，**必然压到邻栏**。`white-space:pre` 又禁止它自己回行。
- 60 句以上的长诗有 18 首，其中 5 首含十言行；这 5 首在 1366 和 1920 都会撞栏（1920 栏 201 也不够 267）。

![1366 长诗全屏：三栏 134px；五言 133.4 贴边，七言 153–187 侵入栏距，十言 267 会撞栏](r7_type/G04_full_long_1366.png)

**改法**

```css
/* 3 栏只在真的放得下时开 */
#c-full .fs-left.long{column-count:2;column-gap:48px}
@media (min-width:1700px){#c-full .fs-left.long{column-count:3;column-gap:44px}}

/* 长诗也吃字号 clamp，但不要低于 21 */
#c-full .fs-left.long .fs-ln{font-size:clamp(21px,min(1.8vw,2.9vh),23px);line-height:1.85}

/* 十言/长句允许回行，不能让 pre 撑破栏 */
#c-full .fs-left.long .fs-ln{white-space:normal;overflow-wrap:anywhere}
```

1366 两栏各约 220px，五言 133、七言 187 都在栏内，十言 267 仍超——所以还要给 `.fs-ln` 允许回行，或在数据层把「五言+五言」补一个「，」，不要渲染成 10 字一行。验收用四首：`秋日夔府咏怀`（5 言）、`八哀诗 赠…李公邕`（7 言）、`夔府书怀四十韵`（10 言）、`北征`（5 言）；1366 下每行 `getBoundingClientRect().width <= colW - 8`。

### 3. 1366 短诗 20px、三级只差 2.5px：版心空，阶梯也没落到底

1366 是这轮最常用的验收档，但短诗的正文被 `min(1.55vw,2.6vh)` 一刀切到 **19.968px**：

- 八句《登高》正文只占 **288 / 742**，页面下半约 220px 是空的；题 32.256、正文 19.968、右栏 `.fs-v` 17.5——**三级只差 2.5px**，正文和右栏几乎同级，诗的视觉重量掉下去了。
- 这不是「小而精」：同屏右栏 17.5 / 2.15 的行距比诗还松；诗是主角，却比注释大不了多少。
- 同一条阶梯上还有两个老问题：全站 108 处 `font-size`，**12.5px 占 60 处（55.6%）**，`var(--tN)` 只被引用 6 次；正文/诗卡/品牌用的 **17.5px 不在** 9/11/12.5/15/23/34/66 七级里；`#sy2 .lab`「生涯」（HTML 569 行）没有规则，落到 UA 默认 **16px**，默认态比相邻「诗云 / 声音」大一号、字距也不同。
- 命中数「237」和 `NO. 0423` 都是 **9px**——最需要被读到的计数用了最小一档。

**改法**

- 按行数分档，不要只看视口：`≤12` 句用 **24–26px / 1.75**（1366 的登高、春望、绝句都能撑住），`13–40` 用 22–23，`>40` 用 20–21；行高统一 1.75–1.8，别让 2.6vh 在 768 高度上砍到 20。
- 把 17.5 收进阶梯（改成 16 或 17.5 并写进 `:root`），把 12.5 的 60 处压到 30 处以内；给 `#sy2 .lab` 补 `font-size:12.5px;letter-spacing:.3em;color:#8a8578`；`#qc` 从 9px 提到 11px。
- 这一档的验收很简单：1366《登高》正文 ≥24px、诗区占比 ≥45%，题/正文/右栏三级差 ≥6px。

## 四、其它必须修（不进前三，但一直拉低质感）

1. **长题在诗卡里也吃头**：68 字题在 1920 卡内 23px / **7 行 / 233px**，1366 把诗区压到 **219px**。卡内题应有 `clamp(18px,…,23px)` 或 3 行 `line-clamp` + 展开，不要和全屏共用 23px（全屏已改成 34 的 clamp）。
2. **搜索输入命中区只有 16px 高**：`#search input` 150×16（68–71 行），视觉上可以，点击目标不合格；建议 `min-height:28px` 或给 `#search` 加 40px 的 `padding`。占位色本身已过（5.7–5.9）。
3. **手机长诗 23px，短诗 15px，优先级反了**：390 短/中诗 `.fs-ln` 15/2（516 行），长诗被 `.fs-left.long .fs-ln` 的 23/1.9 覆盖；200 句在 390 是 **9,743 / 822（11.85 屏）**。长诗在手机上反而更大，建议 390 长诗 17–18px，或把媒体查询写成同级选择器。
4. **短/中/长三套行高没有收口**：`.fs-ln` 1.8、`.fs-left.long .fs-ln` 1.9、媒体查询 2.0；同一个「全屏」三种节奏，读者切换 8 句与 200 句时会感到行距跳档。
5. **原生滚动条箭头**：长诗卡的 9px 金色滚动条带 Windows 三角箭头，和整站的细金线语言不搭；`::-webkit-scrollbar-button{display:none}` 即可，保留 thumb 的金色。
6. **`#hint` 的重复声明**：161 行先 `#8f8a7e` 后 `#6f6b61`，1920 取后者（3.83:1）；≤1500 才变 11px `#8f8a7e`（5.85）。大屏应当更清楚而不是更暗，去掉行尾覆盖即可。
7. **长诗中英混排/标点**：数据里已有「（《苕溪渔隐丛话后集》八云」这类题注混入正文的长行（10 字行的一部分），全屏三栏时它们没有字号/颜色区分，读起来像诗句；建议给「（）」开头的校记行单独降 2px、降一档颜色。
