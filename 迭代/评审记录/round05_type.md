# 字体与编辑设计（字号阶梯 / 竖排 / 行距 / 阅读版式）· 第 5 轮评审

**总分：67 / 100**
**与上轮差：−1（68 → 67）**

实拍口径：Edge headless（--use-angle=swiftshader）经 CDP 实控，锁 1920×1080 / 1366×768 / 768×1024 / 390×844（手机 DPR 2）四档；字号、行高、列数、列高、滚动量全部取 getComputedStyle / getBoundingClientRect，对比度用「文字透明、底色与压暗层保留」的空板逐像素算，水墨层另拍一张连 .art 一起关掉的对照板做差值。实拍 30 余张，文件在 评审/r5_type/。

**②补一刀：这层水墨的「性价比」**

- 全幅：开/关均值都是 15.25，p95 26.63 vs 26.35；只有 **7.2% 的像素变化 >3/255**。

## 三、还剩的三条最伤

### 1. 中间段两栏在 ≤1670px 撑破栏宽：1366 两联并一行、768 压到右栏

这是本轮唯一的**新回归**，也是最贵的一条：不是长诗，是 17–40 行的 271 首（《丽人行》《兵车行》《茅屋为秋风所破歌》《赠卫八处士》都在里面），正好是最常被点开的那一段。

- #c-full .fs-left.mid{column-count:2;column-gap:52px}（263 行）只落了栏数，**没落字号、没设最小栏宽**。
- 1366：(488−52)/2 = **218px** 每栏；.fs-ln 34px + 5.44 字距 = 每字 39.4，七言 **276px**。white-space:pre 让它不可断，多出的 58px 挤进下一栏——两栏叠成一行。
- 768：左栏 278 → 每栏 **113px**，276px 的行不仅跨栏，还盖到右侧「写作时间 / 诗中之意」上面（37 图）。
- 1920 之所以没事，只是左栏 696 → 每栏 322 > 276，**刚好**。

**改法：给 mid 自己的字号，并按栏宽收栏。**（同时把上轮我欠的 23px 补上）

    /* web/index.html:263-265 —— mid 不能只借 long 的栏数 */
    #c-full .fs-left.mid .fs-ln{font-size:23px;line-height:1.95;letter-spacing:.14em}
    @media (max-width:1180px){
      #c-full .fs-left.mid{column-count:1}
      #c-full .fs-left.mid .fs-ln{font-size:26px}
    }
    @media (max-width:820px){
      #c-full .fs-left{column-count:1!important}
      #c-full .fs-left .fs-ln{font-size:23px!important}
    }

校验：1366 每栏 218，23px 七言 = 7×(23+3.22)=**183.5 < 218**；26 行 → 13 排 × 44.8 = **582**，加标题区 330 = 912，1366 上 1.2 屏（现在是 1.9 屏且破），**1920 上 912 < 1058，正好一整屏**——比现在的 1,356 更好。768 单栏 26px，七言 207 < 278，也不再压右栏。

### 2. 1366×768 全屏仍少最后一句；长标题 66px 在 488px 里断成 6+1

- 《登高》1366：正文 34px、行高 74.8，8 句 = 598；标题 66/99 + 作者 + 分隔 + 落款 ≈ 328；总 926 + 上下 padding → scrollH 938，可视 742，**末句「潦倒新停浊酒杯」整句在折线下**，没有任何滚动提示。
- 同一台机上，长题《杂曲歌辞 丽人行》被 66px 断成 **「杂曲歌辞 丽人」/「行」**——一个孤字占一行（fs-t 宽 489，7 字 × 66×1.14 ≈ 527）；1920 上长题《秋日夔府咏怀…》则断在「郑/监」之间。text-wrap:balance 只写进了 <700px 的手机段（491 行），1366 没有。
- 上轮建议的 clamp(23px,4.1vh,34px) 没有落；这一轮全屏的字号仍是两个写死的 34 / 23。

**改法：字号跟视口走，行距同时收到书的口径，标题加 balance + keep-all。**

    /* 267, 270 */
    #c-full .fs-t{font-size:clamp(38px,4.6vw,66px);line-height:1.25;
      text-wrap:balance;word-break:keep-all}
    #c-full .fs-ln{font-size:clamp(23px,min(3.05vw,3.95vh),34px);
      line-height:1.8;letter-spacing:.14em}
    @media (max-height:820px){ #c-full{padding:4vh 6vw 5vh} }

1366：正文落 **30.3px**、行高 54.5 → 8 句 436，标题 62.8/78.5，整块 ≈ **730 < 742**，八句齐；1920：min(58.6,42.7) 仍取上限 34，只是行高 2.2→1.8（74.8→61.2），一屏更稳，也不再是海报密度。标题在 488px 里 balance 成 4+3，不再留孤字。

| 右栏释义 | 17.5px | #c9c3b4 | 10.25 / 9.70 | ✓ |
| 诗句 | 34px | #e6e0d2 | 14.19 / 13.56 | ✓ |
| 诗题 | 66px | #ece7db | 14.48 / 13.73 | ✓ |
| NO.0025 / 英文品牌 | 9px | #4e4b44 | 上轮同色实测 2.28（本轮 CSS 未改） | 等于看不见 |
| <sup>推定</sup> | **10.4167px** | #6a665c | 卡内最小字，讲最需要被知道的事 | 越阶 |

**字阶（源码）**：102 处 font-size，其中 95 处字面量、7 处 token。

- 阶上：9×18、11×4、12.5×**57**、15×2、17.5×3、23×7、34×1、66×1。
- 阶外：clamp(34px,6.4vw,74px)（加载页，1920 取 74）、**clamp(28px,4.6vw,54px)（.phead，355 行，1920 取 54——本轮新长出来的）**。
- 12.5px 一人 57/102（56%），11px 4 处、15px 2 处；var(--tN) 只有 7 处引用，**系统还是 find-replace 的，不是 token 的**——下一轮再加两个元件，13px、15.5px 就会长回来。

**手机**：诗卡 .col 17.5px，全屏 .fs-ln **15px**——「整屏读」比「侧栏看」小一档。335px 宽里，17.5 的七言只有 142px（现在 15px 是 122px），完全放得下。

**改法：先修那行被覆盖的 color，再把三处小字提一档，手机正文回到 17.5。**

    /* 272：同一行里先 #8f8a7e 又 #57544c，后者赢——删掉行尾那个 */

    /* 2028-2032：sup 不再是浏览器默认 smaller */

      margin-left:6px;vertical-align:baseline}            /* 10.4167 → 12.5 */

    /* 355：panel 章节题回到 34 这一档 */
    .phead{font-size:var(--t6)}

    /* 492：手机全屏正文回 17.5，26 行也只多 0.4 屏 */
    @media (max-width:700px){ #c-full .fs-ln{font-size:17.5px;line-height:1.9} }

    /* 221：卡头六段元信息别在括号里断行 */
    #card .mt{text-wrap:pretty}

## 四、竖排与行距：节奏没坏，容器没松

**诗卡竖排（1920）**：17.5px / line-height:2（列宽 35）/ 字距 2.8 / 列间隙 16 → **列轴距 51px = 2.91× 字号**；每字沿列进给 **25.6px = 1.4629×**，七言列高 179。8 列可见 / 200 列 → scrollWidth 10,244 / clientWidth 451 = 22.7×，**可见 4%**。

这张卡这一轮只多了「金色提示」这个出口，容器一格没动：4% 还是 4%，justify-content:flex-start + align-items:center 让《登高》在 323px 的诗区里、179px 的列块上下各空约 72px（五言诗的空带更大——列高 128，空 195）。上一轮我给的「顶对齐 + 列距 41.5」没有落。

**1366 诗卡**：--poem-fs 15、列宽 30、间隙 12 → 列轴距 **42 = 2.8×**，诗区 419 里可见约 10 列。《登高》八列 153px 高，正好贴住 152px 的诗区（10 图）——**这一处是本轮最干净的一笔**。但 fitPoem 的最后一档是 12.5px（1.457×字号），9–11 字的 30 首在 152px 的最坏诗区里仍会上下各切 6–24px；要彻底收口，12.5 下面还得有一档 9px，或让诗区随行数让高。

**全屏行距**：34px / 2.2（74.8）仍是海报密度；1366 的溢出正是它造成的。mid 的 2 栏配 34px 也把「书」变成了「墙」——两栏 972px 高，必须滚动。把 .fs-ln 收到 1.8、mid 收到 23px/1.95，两档才同源。

## 五、一句总评

这一轮把两笔老账真还了：**1366 诗卡的 13px 切字没了，手机全屏终于单列读得下去**；提示也从灰色脚注变成 362 首都能点的金色入口，Esc 与滚动位置都收拾干净了。

但它把「中间段两栏」做成了一个**只在 1920 成立的补丁**——在 1366 它把两句诗并成一行，在 768 它压到解析上。再加上 1366 全屏仍少最后一句、落款仍是 2.63:1 的 #57544c，**67 分：修好两处，压坏一处，最暗的那层小字还是没动。**
