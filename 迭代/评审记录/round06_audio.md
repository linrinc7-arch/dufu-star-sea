## 先说最要命的：开声之后，诗读不了

`web/index.html:1848`（构建里 `杜诗星海.html:1900`）：

```js
function audSelect(pan, pent){ AUD.pent=(typeof pent==='number'?pent:0);
  ...
  base = 196 * Math.pow(2, _pent[_deg%_pent.length]/12);   // ← 少一个 var
```

这个脚本是 `'use strict'`（`web/index.html:619`），给未声明变量赋值直接抛 `ReferenceError: base is not defined`。而 `select()` 在 `2128` 行先调 `audSelect`、到 `2129` 行之后才写卡头、渲诗句——异常把整个开卡流程打断在「星座已经连好、诗卡还没出现」的那一帧。

实测（`err6.json`，真实 Input 事件，不是 `el.click()`）：

| 场景 | 控制台 | `#card.on` | 结果 |
|---|---|---|---|
| 声音**关**，点 `(954,523)` 的星 | 干净 | true | 卡打开，《句》NO.1464，正文 140 字 |
| 声音**开**，点同一颗星 | `ReferenceError: base is not defined` @ index.html:1847 | **false** | 天幕连出星座、悬停标签出现，**卡不出来** |
| 声音**开**，检索「登高」按回车 | 同一条异常 | **false** | 检索框清空了，最匹配的一首没打开 |

图 5 是这一帧：星座、标签、光标环都在，唯独没有诗卡；图 4 是同一颗星在关声时候的样子。

**为什么这是 P0 而不是「声音 bug」**：作品的主循环是「点星 → 读诗」。开声音之后这个循环断了，而且断得很有欺骗性——画面还在动、星座还亮、标签还出，用户只会以为「点了没反应」。同时 `audNoiseVoice`（伪诗）和 `audPaper` 里都是 `var base`，所以**能打开的只剩机器诗**：真诗 1468 首，开声后一首也点不开。这不是「声音层少了一句」，是「声音层掐住了产品」。

**改法（5 分钟）**

```js
var base = 196 * Math.pow(2, _pent[_deg%_pent.length]/12);
```

再在 `select()` 里给声音调用套一层保险，让**任何**声音异常都不能带走诗卡：

```js
try{ audSelect(pan, deg); audPaper(); }catch(e){ /* 声音坏了，卡必须照开 */ }
```

**验收**：开声 → 连点 5 颗星 + 回车检索 → 5 张卡都开、控制台 0 异常；`__AUDIT.events` 里能看到 `['select',pan,0…9]`。

## 这轮真正挣到的

1. **五类界面音的接线是真的。** 不是「写了函数没人调」：`audCue('hover')` 挂在 `pointermove` 的 `hover!==_hoverPrev` 上（1985），`type` 挂在 `input`（2411），`filter/panel` 挂在捕获阶段的 click（2216–2218），`zoom` 挂在 `+/−`（2243–2244）。实测计数与源码一一对上。这是本轮唯一一处「声音第一次覆盖到交互面」。
2. **钟进了同一个房间。** ② 让钟走 `conv`（湿 0.42 / 干 0.65），d30 从上一轮的「直落」变成 1.24s，钟尾和选诗音终于在一个空间里。代价是电平被这次改道顺手削了 3.7dB（见下）。
3. **12 列门槛与提示三档都对**（11 / 12 / 200），回车也真的清空检索态——这两条是能验收的。
4. **上轮修的干路重复没回退**：`audSelect` 仍是 `out→dry→master` + `out→conv→wet→master`，没有第二根直连线；离线下 select 峰值 −17.8 / RMS −25.6，与上轮 −17.8 / −25.8 一致。
5. **每颗星一个音高真的成立了**（度 0–9 实测质心 268 → 904Hz，峰值 −17.8 → −18.9）。方向是对的，只是现在被 P0 挡在门外。

## 这轮输掉的

- **开声 = 读不了诗**（P0，已单列）。
- **界面音不是一套系统，是五个不相干的音。** 代码注释写着「都很轻，峰值比选诗低 10dB 以上」，实测 zoom 比选诗**高 3.6dB**；hover 比底噪 RMS 低 10.8dB，type 低 15.6dB；panel 的 110Hz 正弦在 200Hz 以上**一点能量都没有**（above200 = −101dB）。
- **钟掉到底噪下面。** 100ms RMS −31.0 vs 底噪 −29.3。它在频谱上分得开（钟 85% 在 200–1k，底噪那里只有 5.1%），所以还听得见；但上轮要求的「钟 ≥ 底噪 +2dB」这次成了 −1.7dB，而 ② 正是为了修它才动的刀。
- **机器诗比真诗响。** 伪诗 voice 100ms RMS −24.2，真诗 select −25.6：**伪诗高 1.4dB**。上一轮也是这样（−25.3 vs −25.8），这一轮还在。作品的核心判断是「真/伪有别」，耳朵上却是「伪的更响」。
- **「选诗」先听到的是纸，不是磬。** `audPaper`（3.9kHz 噪声，峰值 −18.8）比青铜磬（−24.6）响 5.8dB；开卡那一下，耳朵先接到的是纸响。
- **同一颗磬，按题哈希浮动 6.7dB。** 度 0（基频 196Hz）在 200Hz 以上只有 −32.5dB，度 9 是 −25.8dB。在笔记本上，**这首诗听起来比那首轻 6.7dB，只因为题目哈希**。

## 三条最伤（按「声音能不能成为作品的一部分」排）

### 1. 开声即崩：一个字，代价是整个主循环

已在上面单列。这里补一条工程视角：这个 bug 能进构建，说明**没有任何一条冒烟测试是「开着声音点一颗星」**。声音段有 0 条自动化断言，而它恰好有一条会抛异常的路径。建议加一条最小回归：

```js
// 开声 → 点星 → 卡必须开
await tap(star);
assert(document.getElementById('card').classList.contains('on'));
assert(errors.length === 0);
```

### 2. 「统一界面音」没有统一电平：−44.9 → −14.2，三类听不见

图 11 是这一条的全部证据。同一套 `audCue` 里：

| 类 | 触发 | 峰值 | 质心 | 200Hz 以上 | 听感 |
|---|---|---:|---:|---:|---|
| hover | 换星 | **−40.1** | 1568Hz | −55.3 | 埋在底噪下 10.8dB，等于没有 |
| type | 打字 | **−44.9** | 1545Hz | −60.9 | 比 hover 还轻 4.8dB |
| filter | 着色/图例 | **−30.5** | 196Hz | −53.8 | 95.8% 在 200Hz 以下 |
| panel | 面板 | **−30.6** | 110Hz | **−101.1** | 200Hz 以上零能量，笔记本上不存在 |
| zoom | +/− | **−14.2** | 2538Hz | −31.2 | 全场最响，比选诗高 3.6dB |

三个毛病叠在一起：

- **电平没归一。** hover 与 type 差 4.8dB，zoom 与 type 差 **30.7dB**。一套「界面音」应该彼此差 ≤3dB、并且整体比「世界音」低 6–10dB；现在是随机数。
- **两类的基频选在了交付设备的悬崖外。** panel 110Hz、filter 196Hz——笔记本小喇叭 200Hz 以下掉 10–20dB，这两类在真机上基本只有触感没有听感。
- **最该被听见的被埋了，最不该响的最响。** 悬停换星是这个作品里**每秒都会发生**的动作，它 −40.1；缩放是**最不承载意义**的动作，它 −14.2。

**改法（约 1.5 小时）**

(a) 给界面音一条**独立总线**，写一次电平，五类都从它出；顺手借 0.12 的湿声，让界面音和星海在同一个房间（现在的 cue 是干的，钟和磬是湿的，同屏两个空间）：

```js
// audInit() 里，conv/wet 建好之后
AUD.cue = ctx.createGain(); AUD.cue.gain.value = 0.30;
AUD.cue.connect(AUD.master);
var cw = ctx.createGain(); cw.gain.value = 0.12;
AUD.cue.connect(AUD.conv);            // conv→wet→master 已在链上
```

(b) 五类各自只调到「峰值 −30±3dBFS」这一条线上，并且**每一类都给一个 2–4ms 的噪声瞬态**（小喇叭靠瞬态定位；纯正弦 4ms 起音在 1.5kHz 上听不出「一下」）：

| 类 | 建议 | 峰值目标 |
|---|---|---:|
| hover | 2093Hz 正弦 70ms **+ 4kHz 噪声 6ms** | −30 |
| type | 2.2kHz 噪声 8ms，高通 1.2kHz | −33 |
| filter | 262Hz 正弦 180ms + 2.6kHz 噪声 10ms | −31 |
| panel | 196Hz 正弦 220ms + 1.5kHz 噪声 12ms | −31 |
| zoom | 600Hz 带通噪声 140ms（把现在的 220ms / 900Hz / 0.55 收掉） | −30 |

(c) 把注释里的承诺变成断言：`peak(cue) ≤ peak(select) − 10`（现在是 +3.6）。

**验收**：五类峰值 −33…−27；盲听 10 次能分清「换星/打字/筛选/面板/缩放」≥9 次；zoom 不再比选诗响；开着底噪时五类都能听出。

### 3. 「夜」还是不在交付设备上，而「呼吸」是死的

| 对象 | 峰值 | 100ms RMS | 质心 | <200Hz | 200–1k |
|---|---:|---:|---:|---:|---:|
| 底噪（本轮） | −22.1 | −29.3 | **85Hz** | **94.8%** | 5.1% |
| 底噪（上轮） | −22.2 | −29.5 | 79Hz | 95% | 5% |
| 随机钟 | −24.6 | −31.0 | 610Hz | 0% | 85.2% |

- ④ 的「620Hz 低通 + 330Hz 分音」把质心从 79 抬到 **85Hz**：+6Hz，`<200Hz` 从 95% 到 94.8%。330Hz 那一根是 0.35 × 0.032 = 0.0112，比 55Hz 的 0.032 低 9dB，加进去只够把质心抬 6Hz。**方向对，幅度差一个数量级。**
- 「呼吸同时改音量与截止频率」实测**什么都没改**：转 180°，`lp 467→468Hz`、`air 0.0158→0.0160`。原因两层：一是 `audFollow` 第 1946–1947 行写的 pitch→380…800Hz，被第 1958 行同一个参数的 `setTargetAtTime` 覆盖（死代码）；二是 `vis`（每 17 个点采样、`zr>0.1` 计数）对 yaw 几乎不敏感——转半圈只差 1 个点。
- 顺带：55/82.5Hz 在笔记本上本来就听不见，`<200Hz 94.8%` 意味着**这一层在交付设备上 ≈ 不存在**；能听见的「夜」其实是 −31.0 的钟和 −17.8 的磬。

**改法（约 1.5 小时）**

(a) 加一层中频，让它做「呼吸」的主角（不是把 330 的音量调大）：

```js
var mid = ctx.createGain(); mid.gain.value = 0.012;
var mlp = ctx.createBiquadFilter(); mlp.type='lowpass'; mlp.frequency.value=900; mlp.Q.value=.5;
mlp.connect(mid); mid.connect(master);
[[220,.018],[277.18,.012],[329.63,.009]].forEach(function(p){
  var o=ctx.createOscillator(); o.type='sine'; o.frequency.value=p[0];
  var g=ctx.createGain(); g.gain.value=p[1]; o.connect(g); g.connect(mlp); o.start();
});
AUD.mid = mid;
```

离线试算：`<200Hz` 会从 94.8% 掉到 ~25%，质心 ~330Hz，RMS 只 +0.4dB。

(b) 呼吸改成**驱动空气层的带通中心频率**，而不是 620Hz 低通；删掉被覆盖的那一行，只留一个驱动源：

```js
function audFollow(){
  if(!AUD.on || !AUD.ctx) return;
  var vis = countVisible();                 // 沿用现有采样逻辑
  var p01 = Math.min(1, vis/450);
  var t = AUD.ctx.currentTime;
  AUD.airBP.frequency.setTargetAtTime(500 + 600*p01, t, 0.8);   // 500→1100Hz
  AUD.air.gain.setTargetAtTime(0.012 + 0.050*p01, t, 1.2);      // 0.012→0.062
  if(AUD.mid) AUD.mid.gain.setTargetAtTime(0.010 + 0.016*p01, t, 1.5);
}
```

(c) 钟把音量补回来：现在 `conv`+`dry` 两道各削一刀，把三根分音的 0.09/0.035/0.014 提到 0.13/0.05/0.02，目标 100ms RMS ≥ 底噪 +2dB（现在 −1.7dB）。

**验收**：模拟 200Hz 高通后底噪仍可闻；转 180° 质心变化 >100Hz（现在 1Hz）；钟 100ms RMS ≥ 底噪 +2dB；`<200Hz` ≤ 30%。

## 一句总评

上一轮的声音层是「很轻的一声叮，加一层听不见的夜」；这一轮它长出了五类界面音、十档音高、一个进了房间的钟——然后在 `base` 上少打了一个 `var`，把「开着声音读诗」这件事整个关掉了。**这轮的问题已经不是「够不够艺术」，而是「开着它还能不能用」**：先让它别坏，再让它成一套，最后才轮到让它在笔记本上听得见。

### 关于两个文件

单文件 `杜诗星海.html` 里写的是 `art/all/0001.jpg`、`art/opt/…`，但 `art/` 在 `web/` 下（826MB），项目根目录没有；所以直接双击单文件时诗卡配图是缺的。实拍因此用 `web/index.html`（资源路径正确）。**两者的声音段逐字节相同**（sha `caeec672415a`），`base` 的缺失在单文件第 1900 行同样存在——这个 P0 与用哪个文件无关。这条打包问题归美术/交付，不占声音的分，但建议顺手把 `art` 一起交付，或把路径改成相对 `web/`。
