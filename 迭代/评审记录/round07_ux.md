## 仍然最伤的三条

### 1. 长题现在不换行了：读页被一首标题撑出 4.4 屏宽（新回归，一行 CSS 能改回）

`#c-full .fs-t` 这轮加了 `text-wrap:balance` 和 `word-break:keep-all`。对中文来说 `keep-all` 的意思是「汉字之间不许断行」——于是长题不是被压小或折行，而是**一路往右跑**：

| 视口 | 标题字号 | 标题实宽 | 所在栏宽 | `#c-full` 横滚 |
| --- | ---: | ---: | ---: | ---: |
| 1920 | 34px | 2,636px | 696.6px | **+850px** |
| 1366 | 32.3px | 2,500px | 488.6px | **+1,245px** |
| 390 | 23px | 1,720px | 335px | **+1,385px** |

- 390 最狠：`@media(max-width:700px)` 把栅格改成 `grid-template-columns:1fr`（没有 `minmax(0,…)`），左栏是 auto 最小宽，被那个不换行的标题**整栏撑到 1,720px**——标题、诗、说明全部跟着跑到屏幕外，页面变成一条 4.4 屏宽的画布。
- 影响面不是个例：34px 在 696px 栏里只放得下约 **18 字**，1366 的 489px 栏只放得下约 **13 字**。全库 1,468 首里，**题长 >18 字有 76 首、>13 字有 181 首**（最长 68 字：《天宝初南曹小司寇舅…》）。
- 反事实我做了：只把 `word-break` 改回 `normal`，390 上标题回到 335px 宽、6 行 186px，`#c-full` 的 `scrollWidth` 从 1,775 回到 **390 = clientWidth**，整页不再能横拖（下图）。

**改法（10 分钟）**

```css
/* web/index.html: #c-full .fs-t */
#c-full .fs-t{column-span:all;font-size:clamp(20px,min(3.2vw,4.2vh),34px);line-height:1.35;
  color:#ece7db;text-align:center;
  text-wrap:balance;
  word-break:normal;            /* 中文照常断行 */
  overflow-wrap:anywhere;       /* 极长的单行也不许撑破 */
  max-width:100%}
#c-full .fs-left{min-width:0}    /* 窄屏单栏栅格：别让内容把栏撑宽 */
```

```css
@media (max-width:700px){ #c-full{grid-template-columns:minmax(0,1fr)} }
```

**验收**：390 / 1366 / 1920 各开三首长题（68 字、33 字、15 字）→ `#c-full.scrollWidth === #c-full.clientWidth`、标题 `getBoundingClientRect().width ≤ 栏宽`、标题 2–6 行、无横向滚动条。

### 2. 卡里的长题还在吃半张卡（③ 只改了全屏，没改卡）

卡题仍是 `font-size:var(--t5)`（23px 固定）+ `padding-right:110px`（给「声音/全屏」两个按钮让位）。390 的卡宽 374px，扣掉 110 只剩 **219px** 给标题——68 字排成 **9 行、300px**：

- 390：卡头 **398px / 844 = 47.2%**，诗区只剩 320px（这首诗 8 句，还看得见；换成《秋日夔府…》200 行，卡里就只剩 610px 的窗口）；
- 1366：卡头 324px / 768 = **42.1%**；1920：374px / 1080 = 34.6%。

而且 `padding-right` 只挡住了「全屏」那一侧，标题文字与「声音 关」按钮在同一行里挨得很近（按钮 y=16–56，标题首行 y≈48），再长一点就会顶上去。

**改法（15 分钟）**

```css
/* 卡题跟随长度收敛，并把 110px 的让位改成「按钮单独一行」 */
#card .tt{font-size:clamp(17px,2.1vw,23px);text-wrap:balance;word-break:normal}
@media (max-width:700px){
  #card .hd{padding-top:62px}          /* 让出按钮那一行 */
  #card .tt{padding-right:0}
  #card .readtoggle{top:14px}
  #close{top:14px}
}
```

**验收**：390 / 1366 打开最长题 → 卡头 ≤ 30% 卡高、标题与两个按钮零重叠（`overlap(title,csound)===0`）、标题 ≤ 5 行。

## 另外四条（次伤，但别过夜）

**A. 长诗全屏没有位置感。** 200 行在 1920 是 **3.0 屏**（3,159/1,058）、1366 **4.2 屏**（3,145/746）、390 **11.8 屏**（9,720/822），全站没有进度条、没有页码。改：`<div id=fsprog><i></i></div>` + `#c-full` 的 `scroll` 里写宽度；≤700 另给「写作时间 · 诗中之意 ↘」锚点。验收：滚到底进度条 100%，200 行首尾各 1 屏内可达。

**B. 「共 200 列」这句现在说错了。** `_need ? '共 '+p.L.length+' 列'` 是给竖排写的；`>40` 行走横排后它们已经是**行**。一行改法：`(p.L.length>40?'行':'列')`。顺带把提示条从 28px 补到 40px（它现在也是「点这里整屏读」的触发区）。

**C. POEMS 那行还是 2.36:1。** `#meta-r .num{color:#55524a}` 没动；金色数字之外的字（`POEMS`、`712—770`）在实测底 (11,8,8) 上仍是 2.36:1。改成 `#8a8578` 即 4.9:1，一个字符。

**D. 键盘与读屏仍是零。** 卡片关着时 Tab 顺序是：输入框 → 页脚声音 → **隐藏卡片里的「声音 关」→ 隐藏的 `#c-poem`（`overflow:auto` 被浏览器塞进 Tab 序列）** → BODY。全站 `:focus-visible` 0 条、`aria-live` 0 条、`inert` 0 处、`prefers-reduced-motion` 0 条。最低限度：卡关时 `#card{inert}`、`#qc{aria-live="polite"}`、reduce 下关自动旋转与逐字入场。

## 一句总评
