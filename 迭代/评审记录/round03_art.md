## 三条问题（现在仍然最伤）

### 1. 天幕把“星”吃掉了：可辨识星峰 −43%，星:地 40:1 → 6.5:1，12 处题名同时归零

- **亮度预算全花在气氛上。** 星没变暗，但地变亮了 6 倍：天幕区 p50 **5.22 → 33.31**，L 在 40–80 的像素从 **2.8% 涨到 32.5%**——这一档正好是诗星光晕所在的亮度。结果 `p99.9/p50` 从 **40.4 掉到 6.5**，2×2 放大用肉眼也能看出：星不再“扎”在黑底上，而是浮在粉蓝的雾里。
- **能“跳出来”的星少了四成。** 以 24×24 块中值为地面，统计 3×3 局部极大值：Δ>80 的峰 **2235 → 1274**；Δ>50 的峰只从 2818 → 2803（没少）。也就是说 1,468 颗诗**还在**，但“一眼能挑出来”的那一层掉了一半——观众看到的是“一片噪点”，不是“一些星”。
- **天上现在没有一处字。** R2 有 12 处《诗题》作为读图索引（`r2_01` 在 (930,450) 有「《登高》」，见 `c_label_denggao.png` 上下一屏对比）。本轮 DOM 里**已经不存在任何 `《` 文本**（只有 `<script>` 里的字符串），我把 `body *` 的叶子节点全扫了一遍，无一是题名。天空于是退化成纯肌理：除了 hover，没有任何办法知道哪颗是《登高》。**这条和“太亮”是同一件事的两面**——天幕一忙，索引就被拿掉了。

### 2. 三层色只交付了两层：洋红成了最抢眼又最没意义的一层，赭金退成右下角一块卡其污渍

- **配比和承诺不符。** 代码里写的是“青蓝反射 / 洋红电离氢 / 赭金尘埃”，画面实测是 **蓝 70.7%、洋红 17.0%、赭金 0.5%**。R2 的十色图例在场上还能对上号（金 17.7%、红 27.6% 之类，六个语义色族占 61%），本轮这六族只剩 **3.0%**——图例还在，语义色在画面里没了对照物。
- **撞色。** 天幕蓝的色相 **209°**，图例「日月」的 dot 是 rgb(143,184,222) = **208.4°**。天幕把“日月”这个类别泡进了自己的底色里，这一类星失去了背景分离。
- **赭金变成污渍。** 唯一像“金”的地方是右下 (1180–1600, 900–1080) 一大团卡其色，2.2× 下能看到明显的 8 位色阶网纹（`c_goldsmudge.png`）——它不是“尘埃带边上被照亮的金”，而是一块**没有形状的米色涂抹**，还正好压在底栏图例的上方，是全画面第二亮的区块。
- **洋红没有任何语义。** 它是场上最高饱和、最“看这里”的颜色，形状也最抢（丝状卷须），但它不代表任何东西——真正承载意义的十个颜色反而退到星核的 0.1% 里。

### 3. 全屏读诗页仍是黑屏，而且栏流把标题和诗都切错了（连续两轮未动）

- **还是黑屏。** 全屏 200×400 平坦区 mean **9.53 / std 5.20**，整页 mean **12.57 / p50 9.79 / 29.7% 的像素 < L8**（R2 为 11.18 / 8.29 / 41.6%）。这一轮加的是 `#card.reading` 顶部一团暖色径向渐变：顶部取样 (22,19,15)，比底色只高 3 个数——**是一层“灯罩味”的雾气，不是材料**。水墨仍然被 `#card.reading .art{display:none!important}`（:233）关掉，全片唯一的笔触进不了这一页。
- **栏流把版面切坏了两处**（根因同一个：`.fs-left{column-count:2}` 没有 `column-span:all`，报头也在栏流里）：
  - 《登高》8 行被切成 **3 / 5**：第 1 栏首行 y=411，第 2 栏首行 y=**266**——两半**错位 145px**，右栏比左栏高出一整行，读起来像排版事故而不是设计。
  - 200 行的长标题被 320px 的栏宽压成 **42px × 6 字 / 行、共 3 行**，断在「奉寄郑监李宾 / 客一百韵」——**把专名「李宾客」劈开了**，R2 提的“标题断在词里”原样复现。
  - 另外 `.fs-left.long{column-count:3}`（:255）是死规则：没有任何 JS 加 `.long`（实测 `columnCount` 仍为 2），所以 200 行还是两栏 100 行。

## 三条改法

### 改法 1：给天幕一条“起黑”曲线 + 一张低频密度图，把对比预算还给星；题名按新亮度重挂

`buildNebulaTex()`（web/index.html:951–1020）三处 + `drawNebula()` 一处：

```js
// ① 低频密度：让天幕有“核心 / 空场”，不要满屏一个密度
var big = nFbm(dx*0.75+31.7, dy*0.75, dz*0.75, 2);
dens *= 0.35 + 1.55*Math.pow(Math.max(0, big-0.34), 0.9);

// ② 起黑 + 提对比（放在 987–989 的 exp 色调映射之后）
var k=1.38, bp=14;
d[i4]  = Math.min(255, Math.max(0,(v0-bp)*k));
d[i4+1]= Math.min(255, Math.max(0,(v1-bp)*k));
d[i4+2]= Math.min(255, Math.max(0,(v2-bp)*k));

// ③ 细星不能被压：1001 行的 alpha 抬底
var a = 0.28 + r*r*0.72;          // 原 0.10+r*r*0.75

// ④ drawNebula() 合成时收一档（1033 行）
ctx.globalAlpha = 0.62;           // 原 0.95
```

A/B 实测（`r3_06_ab1_dim.png`，只做 ②④ 的 alpha .55 + 起黑）：天幕区 p50 **33.2 → 20.8**、%L<20 **28.5 → 48.4**、星:地 **6.5 → 10.0**。**但**只做亮度会把贴图里的 5,200 颗细星一起压掉（局部极大值 Δ>50 由 2803 掉到 1349），所以 ③ 必须同时上——否则换来的是“干净但空”的天。

题名按新亮度重挂：恢复到 R2 的 12 处，`.tl{text-shadow:0 0 10px #04050a,0 0 3px #04050a}` 或用 40% 黑的 1px 底衬；**验收**：同机位下能数出 ≥10 处《诗题》，每处局部对比 ≥ 3:1。

### 改法 2：洋红挪到“脊线”、赭金挪到“尘埃带”、蓝色偏 13° 让开「日月」

`buildNebulaTex()` 的权重与色值（:977–983）：

```js
// 青蓝：色相 209° → 196°，与图例「日月」208° 拉开
var wB=Math.exp(-Math.pow((dens-0.22)/0.34,2));
// 洋红：从“整片面”收到“电离前沿的脊”，且压暗，不再抢
var wM=Math.exp(-Math.pow((dens-0.62)/0.13,2))*0.85;
// 赭金：不再按 dens 取，改按尘埃取——它应该长在暗带边上
var wG=Math.pow(dust,1.35)*2.6;
var cr=(wB*36 + wM*150 + wG*198)/sum;
var cg=(wB*138 + wM*44 + wG*132)/sum;
var cb=(wB*190 + wM*96  + wG*74 )/sum;
```

A/B（`r3_07_ab2_palette.png`，把洋红收窄 + 蓝扩宽）：蓝 **88.8% / 洋红 3.9%**——证明“收洋红”这个旋钮确实有效，但收过头就没有第三层了，所以上面用 `wG` 从 dust 取金来补位。**验收**：三层占比落在 **蓝 60–70 / 洋红 8–12 / 赭金 8–12**，且赭金只出现在暗带边缘（不出现 >200px 的连片米色团）。

### 改法 3：把报头从栏流里拎出来 + 水墨搬回全屏（一条 `column-span`、一条长手写背景）



## 一句总评

这一轮把“没有天”补上了——第一次有光、有颜色、有材料，而且是算出来的；但它把亮度预算几乎全给了气氛：**星没变少，能看见的星少了一半；天上的确有星海，却再没有一处字告诉你那是《登高》**。天幕现在比诗好看，这就是它只值 +2 的原因。
