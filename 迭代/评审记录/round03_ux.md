## 仍然最伤的三条

### 1. 触屏点星是死路：点《赠李白》抛异常，什么也不发生

- 机制一：`click()` 只认 `hover`，而 `hover` 只在 `pointermove` 里由 `pick()` 更新（1930 行）。**触摸没有 pointermove**，所以 `hover` 恒为 null，点什么都落到 `pcPick()` 的"白噪音星"分支。
- 机制二：`selectNoise()` 是从 `select()` 复制的，尾巴里还留着 `p`：
  - 1950 行 `var col=(window.COLLATION||{})[p.t];`
  - 1988 行 `hint.textContent = p.L.length>=24 ? …`
  - `p` 在该函数作用域里不存在 → **ReferenceError**，而且抛在 `card.classList.add('on')` **之前**。
- 实测（390×844，`_r3/r3_10_mobile_tap.png`）：tap《赠李白》→ `Uncaught ReferenceError: p is not defined`，`card.className === ""`，`sel === null`。用户看到的是：**点了一颗亮星，毫无反应**。
- 这不是"移动端优化没做"，是**移动端根本打不开诗**。同一份代码在触屏笔记本、平板、手机上都是这个结果。
- 如果这版明确只做桌面，就把 `@media (max-width:1000px)` 的移动布局和触屏语义一起砍掉、在窄屏给一句"请用桌面打开"；现在这套是"看起来支持手机、点下去是空的"，比不支持更糟。

**改法（两处，约 15 分钟）**

```js
// 1930 行：点的时候按当前帧重算一次，别信 pointermove 留下的快照
function click(mx,my){
  pick(mx,my);
  if(hover){ select(hover); return; }
  var po=pcPick(mx,my,18);
  if(po) selectNoise(po);
}
```

```js
// selectNoise：把 p. 改成 po.（1988 行那段「共 N 列」是诗卡逻辑，白噪音卡不需要，删）
var col=(window.COLLATION||{})[po.t];
```

```css
#sky{touch-action:none}   /* 否则拖拽巡游会被浏览器当成页面滚动 */
```

**验收**：390×844 触摸点名篇星 → 卡片打开且标题与星一致；点白噪音星 → 卡片出现、带「机器」标记、控制台 0 异常；拖拽能转天幕、不带动页面。

### 2. 入口被新天幕吃掉了：0 个题名、1.88:1 的检索、5,200 颗假星

- **题名层被整个撤掉**：上轮 12 个 canvas 题名虽然点不中，至少能"看见今天有什么"；这版 `fillText` 为 0，首屏**没有任何一个诗题**。想读一首指定的诗，只剩两个入口：悬停（触屏没有）和一个你看不见的输入框。
- **检索框还是隐身的**：placeholder 颜色 `#3F3D37`（72 行），实测 **1.88:1**；`#search` 只有 187×24、1px 下划线。上轮把它归因于暗角，暗角这轮修了（z14→5），但字本身的对比度没动——**这不是遮挡问题，是颜色问题**。
- **唯一的概念数字也在隐身**：`POEMS 1468 · 712—770` 是 9px、`#55524A`、**2.60:1**。整个作品的命题（"1,468 首散在天上"）全靠这行小字。
- **新天幕带来了 5,200 颗假星**：`buildNebulaTex()` 往贴图里 `fillRect` 了 5,200 颗星（1003 行起），尺寸 1–1.6px、亮度最高接近白色；它们不可点、不悬停、不参与任何语义，却和真诗、和 24,000 粒可点噪声长得一样。实测取 7 个"离任何诗星 ≥55px"的亮点逐个悬停：**2 个**能唤出提示（《团武处即事》《沔彭台梦》，都是机器诗），**5 个**什么都不发生；其中最亮的那颗（L=0.419，比多数真诗还亮）点下去连卡片都不开。
- 顺带：设计文档写「白噪音不许抢焦点」，现在贴图里的死星是最亮的一层碎点，抢的正是焦点。

**改法（三步，约 40 分钟）**

```css
#search input::placeholder{color:#8a8578}     /* 5.7:1 */
#meta-r .num{color:#8a8578}                    /* 5.7:1 */
#search{min-height:34px;border-bottom-color:rgba(236,231,219,.24)}
#search input{font-size:13px;width:190px}
```

```js
// 1003 行：贴图里的星只当颗粒，不当"可点的星"
var a=0.05+r*r*0.16;          // 原 0.10+r*r*0.75
g.fillRect(sx,sy,1,1);        // 原 1.0/1.6px
```

再给天空一个**不依赖悬停**的名字入口：把上轮的 `#lablayer` 捡回来，但只给 12 首名篇，而且 `onclick` 绑自己的 `p`（不再用 26px 星距去猜）；`@media (pointer:coarse)` 下不显示 label，改为在底栏上方放一行 6 个名篇 chip（源起面板里已经有「从《登高》开始」的现成写法，搬到首屏即可）。

**验收**：placeholder 实测 ≥4.5:1；`#meta-r .num` ≥4.5:1；手机首屏能看见至少 6 个诗题并点开；随机点 20 个亮点，凡是有反馈的都必须是可读内容（诗或明确标注的白噪音），不允许"亮着但死了"。

### 3. 200 行的诗，在卡片里还是只露出开头 10 列

## 另外两条（次伤，但都不该留到下一轮）

**A. 加载进度是假的。** `buildNebulaTex()` 在启动处同步跑（2895 行），6× 节流下是一个 **7.07 s 的长任务**；`PICKING STARS 0000 / 1468` 的计数器在它之后才 `setInterval` 起步，所以整段冻结期数字一直是 **0000**。1× 下首屏 4.81 s 尚可接受，慢机上就是 11.61 s 的黑屏加一个不动的 0。改法：先 `requestAnimationFrame` 画一帧再算（或把 1,024 行切片分帧算），并让计数来自真实阶段（量星 / 铺天幕 / 点诗 / 聚光）。设计文档原话是「不要用动画掩盖加载」，现在正是反例。

![6× 节流：0000 卡住 7 秒](<_r3/r3_11_load_6x_3s.png>)

**B. 键盘与读屏基本为零。** `<button>` 0 个、`aria-live` 0 个、`h1` 0 个、卡片无 `role`/`inert`；Tab 只有 3 站（`#q`、`#autog`、以及**卡片收起时仍在 Tab 序列里的 `#csound`**），`readtoggle`/`close` 是 `tabIndex −1` 的 div。另外没有 `prefers-reduced-motion`：自动旋转、星点呼吸、伪诗下落、逐字入场全都在跑。最低限度：给 `#search` 一个 `aria-label`、给结果数 `aria-live="polite"`、卡片开合切 `inert`、补 `:focus-visible` 描边；`matchMedia('(prefers-reduced-motion:reduce)')` 为真时关掉 `autoSpin` 与逐字入场。

## 一句总评

天幕这轮做到位了——深空、丝状、三层色，是这版最像"作品"的一屏；长诗全屏也终于站住了。但用户要点开它，得先摸到一个看不见的输入框，或者在一堆分不清真假的亮点里赌一颗星，而手机上连赌的机会都没有。**先把"点得开"修回来，再谈"看得见"。**
