## 最伤的三个问题（每条带证据）

### 1. 星璇核心过曝成一坨白，放大看还是方块像素——全片唯一的主角，做成了全图信息量最低的地方

证据：

- `评审/img/rev_art_default.png` 默认视角，核心 (880,440)–(1050,600) 这 170×160 的区域：**12.1% 的像素是纯白 ≥250**，亮部平均 RGB(234,234,232)。三个通道几乎相等，意味着连色相都被一起削掉了——不是「亮」，是「糊」。
- `评审/img/rev_art_zoomcore.png`（zoom 3.4）打开核：所谓「星璇」是一堆**轴对齐的 1–3 px 实心方块**，边缘是硬的，没有衰减、没有大小层次、没有前后遮挡。读起来是「撒了一把米」或者「像素尘」，不是星。
- 源码印证：`drawPoemCloud()` 里 `ctx.fillRect(sx-sz*0.5, sy2-sz*0.5, sz, sz)`，`sz` 只有 3 档 ≈1.2/1.9/2.9 px；`globalCompositeOperation=lighter`；`globalAlpha = 0.10 + 0.34*tw`。22000 个方块在加法混合下无限叠加且**没有任何 tone mapping**，核必然烧穿。
- 后果：眼球落到画面中心，那里是一块没有结构、没有颜色、没有边缘的亮斑——这是「死焦点」，最亮的地方恰恰是最没东西看的地方。作品的概念卖点（中心是九万首伪诗构成的星璇）在这一帧里完全不可读：我在 3.4× 下也找不到任何字形。

### 2. 意象色彩系统在画面里不存在，金色 UI 却最亮——数据可视化层退化成装饰

证据：

- 图例（底部）列出 10 类意象色：日月 / 江山 / 草木 / 乌兽 / 器物 / 病痾 / 愁思 / 兵戈 / 亲故 / 释道。但全图**亮度>120 的像素里 51.4% 色度<0.10**，平均色度只有 0.131。画面上过半的「亮东西」是中性灰白。
- 成因在源码，是三层的系统性洗白：`SPR[c.id] = makeSprite(mute(c.color, 0.34))` 先把类别色洗白 34%，再叠一层 `globalAlpha≈.26` 的近白辉光，最后被加法混合削顶。
- 白噪音云更极端：`drawPoemCloud` 只有两种颜色 `rgba(255,238,200)` 与 `rgba(198,214,255)`，两色只差 30 个 RGB 值，在 3 px 尺度上根本分辨不出来。
- 反观 UI：`.kw span.on` / `.rel i.on` / `#sy .s.on` / `.readtoggle` 的选中态统统是 `background: var(--gold); color:#04050a` 的实心金块。在 90.5% 像素亮度<8 的画面上，左下角那两块 `#c9a227` 实心金是**全屏对比度最高的东西**——视线先被两个「意象」金块勾走，再去找银河。
- 后果：「1468 首诗的语义空间」这句话在画面上不成立。观众读到的是「一团白星 + 两块金按钮」，山水与兵戈同色，愁思与释道同色。

### 3. 读诗这一层全面失守：全屏是死黑，水墨被扔掉，而 z-index:29 的暗角还在压着卡片

证据（三件事叠在一起，逐条可复测）：

- **`#vig` 盖在卡片上面。** `#vig{z-index:29}`，而 `#card{z-index:16}`。我量了 `rev_art_card.png` 里《登高》八列字的峰值亮度，从右到左是 **158 → 163 → 170 → 177 → 184 → 190 → 196 → 202**，严格单调。第一行「风急天高猿啸哀」比最后一行「潦倒新停浊酒杯」暗 **22%**。首行是一首诗的门面，被自己的暗角吃掉。
- **全屏阅读没有任何材质。** `#card.reading .art{display:none!important}` 把卡片顶那张水墨（全片唯一有笔触、有温度的材料，410×215）直接扔了，换 `#06070c` 平涂。实测 200×400 平坦区：**均值 4.96，标准差 0.53，min 4 / max 6**——死平。`#grain` 明明在（`opacity:.055; mix-blend-mode:overlay`），但 overlay 叠在 #04050a 上等于没加，std 只有 0.53。
- **卡片里诗只占 17%。** 1080 px 高的卡片：0–215 配图，215–465 元信息，**475–655 才是诗**，655–880 是 225 px 纯空，880–1080 脚注。而脚注「依据 · 词典命中 22 处…」「近邻 · 《收京三首》…」是 `.evd{font-size:9.5px;color:#57544c}`，在 #090b11 上约 **2.7:1**；`NO.0828` 是 9 px `#4e4b44`，约 **2.3:1**。这个产品真正的学术价值，被排成了全页最不可读的文字。

（附带一条可以顺手查的：`.poem` 上挂着 `mask-image:linear-gradient(to left,#000 94%,rgba(0,0,0,.15) 100%)` 这条渐隐装饰。修完 `#vig` 之后要重新量一次八列峰值，确认这条 mask 没有落到正文列上。）

## 三条改法（每条具体到怎么改）

### 改法 1：给星璇做 tone mapping、换掉方块粒子（落 JS，动的是 `drawPoemCloud`）

**1.1 粒子换 sprite。** 现在是：

```js
ctx.fillStyle = PC.warm[i] ? "rgba(255,238,200,1)" : "rgba(198,214,255,1)";
ctx.fillRect(sx - sz*0.5, sy2 - sz*0.5, sz, sz);
```

改成两色各预渲染一张 16×16 径向 sprite（`createRadialGradient`：中心 alpha 1 → 55% 处 0.38 → 边缘 0），画的时候 `ctx.drawImage(spr, sx-sz, sy2-sz, sz*2, sz*2)`；`sz` 三档底数从 1.0/1.6/2.4 提到 **2.2/3.4/4.6**（软点比硬方块耐叠）。

**1.2 按深度衰减，别均匀叠。** 在 `if(zz<=0.05) continue;` 之后插入：

```js
var dz = 1 / Math.max(.28, zz);
sz *= (0.60 + 0.50*dz);
a  *= Math.min(1, 0.55*dz + 0.35);   // 近的亮、远的淡
if (zz < 0.35) continue;            // 核后面那一层直接剪掉，别穿帮
```

验收标准：核心区 ≥250 的像素从 **12.1% 压到 <3%**。

**1.3 加一道后处理（只跑 720p buffer，成本 <3ms）。** 把云画到离屏 canvas，收尾时 `ctx.filter="contrast(1.40) saturate(1.18) brightness(.90)"` 再 drawImage 回主画布。这一步是让白团里的结构回来——没有它，1.1 和 1.2 都只是把白团变暗一点。

**1.4 收星芒。** `hot` 星的 `halo` alpha 上限 `.34 → .18`，四芒长度乘 `(0.7 + 0.3*cam.dist/q.d)`，`lineWidth .7 → .55`。数据里 `hot=1` 的诗正好 **38 首**，38 枚同尺寸十字芒铺满画面，是「贴纸感」的主要来源。

### 改法 2：把色彩还回去，把金色让出去（落 JS + CSS）

**2.1 别洗白类别色。** `SPR[c.id] = makeSprite(mute(c.color, 0.34))` → `mute(c.color, 0.10)`；`mute` 的实现从「混白」改成「只降明度不降饱和」（保持 HSL 的 `s`，`l` 降 8%）。

**2.2 辉光要带色。** 现在 `globalAlpha≈.26` 画的是同一张被洗白的 sprite 放大 3.1 倍。改成按 `colOf(q0)` 现生成 64 px 径向渐变缓存（中心 `rgba(color,.55)` → 70% `rgba(color,.12)` → 0），alpha 上限 `.26 → .14`。这样每颗诗星是「带色小核 + 带色雾」，而不是「白针尖」。

**2.3 全局提饱和。** render 末尾对合成图加 `saturate(1.5)`，与 1.3 合并成一次 filter 调用，不额外开一遍。

**2.4 金色降级为描边。** 四处选中态置换成：

```css
.kw span.on, .rel i.on, #sy .s.on {
  background: transparent;
  border-color: rgba(201,162,39,.80);
  color: var(--gold);
  box-shadow: 0 0 14px rgba(201,162,39,.12);
}
```

**实心金只留给「名篇」徽标一处**——它是唯一的「这篇值得读」信号，必须独占最高权重。

**2.5 顺手去重（文案 + 结构）。** 底部两行各有一个实心金「意象」（`检索` 行一个、`着色` 行一个），视觉上完全同构、语义上完全不同，行标 `检索/着色` 又是全行最小最暗的字。改成一个二段控件 `查 | 显`，两行默认不同值，别让人一进来看到两个都亮着的「意象」。

**2.6 图例要能对得上画面。** 10 个图例点从 6 px 提到 8 px 并加 `box-shadow:0 0 14px currentColor`；点击图例时复用已有的 `focusSet` 分支（`a=Math.min(1.7,a*1.6+0.3)`），让被选中的类别在银河里真的整片亮起来——现在这条通路只对搜索词生效，图例是死的。

### 改法 3：把水墨搬进全屏、修 z-index、把纸做出来（落 CSS + JS + 文案）

**3.1 修层级（一行，收益最大）。** `#vig{z-index:29}` → `z-index:1`（只压 canvas），或反过来 `#card{z-index:31}`、`#panel{z-index:32}`。改完重拍，八列峰值应回到 200±2。**这条不修，后面所有排版调整都会被暗角再吃掉 20%。**

**3.2 全屏保留水墨。** 删掉 `#card.reading .art{display:none!important}`，在 `openPanel` 里写变量：

```js
document.documentElement.style.setProperty("--hero", "url(" + p.img + ")");
```

```css
#card.reading::before {
  content: ""; position: fixed; inset: 0; pointer-events: none;
  background: var(--hero) center / cover;
  filter: grayscale(1) contrast(1.3) brightness(.62);
  mix-blend-mode: screen; opacity: .13;
}
#c-full { background: #06070c; position: relative; z-index: 1; }
```

水墨在 13% 上做 `screen`，正好是宣纸透墨的观感——读诗页立刻从「黑网页」变成「纸」。全套里投入产出比最高的一条。

**3.3 把颗粒做到看得见。** 纯黑上 `overlay` 无效。改 `#grain{opacity:.10; mix-blend-mode:screen;}`，并把颗粒源图从深灰提到中灰 `#8c8c8c`（或 `feTurbulence baseFrequency=.9` 现生成）。验收标准很硬：**平坦区 std 从 0.53 提到 2.5–3.5**，全屏 p95 亮度从 7.1 提到 10 左右。

**3.4 卡片里给诗让位。** `.poem` 加 `align-items:center`，把算 `--poem-fs` 的那段 JS 乘 1.15；让 7 行字吃满 475–820 这一段（现在只占 180 px，下面空 225 px）。脚注字号：`.evd{font-size:9.5px;color:#57544c}` → `11px; color:#8f8a7d`（≈4.9:1）；`.no` 从 `#4e4b44` → `#7d7869`（≈4.0:1）。

**3.5 文案：把交互提示从正文里拆出来。** 卡片底部「把指针停在线上，可以看到这两首共享哪个词」现在和正文同字号同色，读起来像正文。改：

> ↳ 悬停连线，看两首诗共享的那个词

加 `class="tip"`，`font-size:10px; color:#6f6b61; font-style:normal`，前置 `↳` 与正文分开。

## 一句总评

底色和排版是有底子的——水墨、金线、宋体宽字距、留白的克制都对；但这个作品的核心承诺「把 1468 首诗的语义空间排成一枚银河」，在成品里既没有颜色，也没有结构：核烧成了一块白，意象色被洗成了灰，读诗页又退回一块死黑。等于把一个很好的概念，做成了「一张漂亮的星野壁纸 + 一个很讲究的侧栏」。
