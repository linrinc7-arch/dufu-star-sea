# 字体与编辑设计（字号阶梯 / 竖排 / 行距 / 阅读版式）· 第 4 轮评审

**总分：68 / 100**
**与上轮差：+3（65 → 68）**

实拍口径：Edge headless（`--use-angle=swiftshader`）经 CDP 实控，先 `Emulation.setDeviceMetricsOverride` 锁 1920×1080 / 1366×768，等程序化星云算完（≈6.5 s）再采；字号、行高、列数、滚动量、越界值全部取自 `getComputedStyle` / `getBoundingClientRect`；对比度取"文字透明、底色与压暗层保留"的空板逐像素算，另拍一张连顶/底栏压暗一起隐去的对照板做差值。实拍 35 张：1920 主图 6、1366 主图 7、2×/3× 局部 13（另有一轮 `deviceScaleFactor:2` 的整倍率实拍）、空板 5、滚动与继承态 3、加载页 1，文件在 `评审/r4_type/`。

> 结论先说：**字号这一刀切干净了**——源码 89 处 `px` 声明全部落在 8 档上（上一轮 20 多个值、7 个在阶外），运行时也只有一处越阶（`sup` 的 10.4167px）。**全屏版式也终于站住了**：短诗单栏 8/8 句，长诗三栏 67/67/66，右栏 sticky 滚到 1,400px 仍在原位。**但 1366×768 这台最普通的笔记本上，诗卡把每列的头尾各切掉 13px，全屏把最后两句推到折线以下**——"读不全"从 1920 搬到了 1366，没有消失。68 分：这一轮把"阶"修好了，"场"没跟着修。

## 三、还剩的三条最伤

### 1. 1366×768 读不全：诗卡切头尾 13px，全屏少两句

这是这轮唯一的**新回归**，也是最贵的：受影响的不是长诗，是 365 首七言——包括《登高》《秋兴八首》《咏怀古迹五首》这些挂在首屏的名字。

**诗卡（1366×768）**

- 卡高 768 = 配图 **150** + 卡头 **194** + 卡脚 **271** + 诗区 **153**。
- 七言列高 **179px**（每字进给 25.6px × 7），装进 153px 的框，`align-items:center` 让它两头各溢出 13px。
- `scrollH=180 > clientH=153`，但上溢部分在滚动区外——**滚也看不到"风"和"哀"**。
- 上一轮我给了 +3，理由是 1366 的七律"`clientH=232`、列高 158.5、56 字全在框内"；这一轮布局一改，那条 +3 又赔回去了。

![1366 诗卡 3×：《登高》每列的头尾各被切掉一大半](r4_type/39_clip_1366_3x.png)

![1366 全屏：末两句在折线下](r4_type/11_full_denggao_1366.png)

**改法：让 `fitPoem` 真的把字号落下去——它现在就摆在 2388 行，算完就扔。**

```js
// web/index.html:2388 起，整段替换
function fitPoem(p){
  var el=document.getElementById('c-poem');
  if(!el||!p||!p.L||!p.L.length) return;
  var maxLen=Math.max.apply(null, p.L.map(function(s){return s.length;}));
  var ADV=1.4629;                       // 实测：竖排每字进给 = 1.4629 × 字号
  var avail=(el.clientHeight||420)-18;  // 上下各留 9px
  var fit=avail/(maxLen*ADV);
  var LADDER=[17.5,15,12.5];            // 只在阶上取，不再自造 15.5/13.5
  var fs=LADDER.filter(function(v){return v<=fit;})[0]||12.5;
  el.style.setProperty('--poem-fs', fs+'px');
}
```

```css
/* 449 行的 --poem-fs:15.5px 是死代码：448 行把 .col 写死成 17.5px，特异性更高 */
@media (max-width:1500px){
  #card .col{font-size:var(--poem-fs,17.5px);line-height:1.9}   /* 改这一行 */
}
@media (max-height:820px){
  #card .art{height:110px}                 /* 150 → 110，把 40px 还给诗 */
  #card .ft{max-height:212px;overflow:auto}/* 271 → 212，卡脚可滚 */
}
```

按现在的 153px 框，`fit=13.2` → 落 12.5px，七言列高 128px，**立刻不切**；若同时把配图/卡脚各让 40–60px，框到 213px，`fit=17.1` → 落 15px，仍然不切——**15px 这一档本来就是空的**，正好用在这里。

**全屏（1366×768）**

```css
/* 262 行：字号跟视口走，行距同时收一点 */

#c-full .fs-t{line-height:1.15}            /* 99 → 76 */
#c-full .fs-note{margin-top:18px}
@media (max-height:820px){ #c-full{padding:3.5vh 6vw 4.5vh} }
```

768 高时：正文 31.5px、行高 56.7 × 8 = 454，加标题/署名/分隔/落款约 250 → **≈704 < 742，八句齐**；1080 高时 4.1vh 已超上限，仍是 34px，1920 的观感不动。**注意这条把"34 与 23 之间没有台阶"暴露出来了**：1366 要在"溢出"和"掉到 23px"之间二选一，fluid 是唯一不破坏阶的解法。

### 2. 17–60 行的"中间段"（271 首）全屏是单栏 2–4 屏；读另一首从中间开始

- 行数分布：1–8 行 **1012**、9–16 行 **167**、**17–60 行 271**、61–120 行 **16**、121+ 行 **2**。
- 三栏只给 >60 行的 **18 首（1.2%）**；271 首中间段走 `cc=1` + 34px + 2.2 行高：26 行《丽人行》= **2,328px（2.3 屏）**，60 行 = **4,488px（4.4 屏）**。
- 单栏宽 690px，正文只占 272px——两侧各 200px 空着，一路空 2–4 屏。
- 更要命的是**位置继承**：从长诗全屏退出、换一首再进，`scrollTop` 不重置（实测 1,300），标题在 `y=−1183`，读者从诗中间开始读，还不知道这是哪一首。

### 3. 字阶收了口，但没分工；小字对比度一格没动

**分口不均**（这是"8 档"落地后的真问题，不是又一个数字游戏）：

| 档 | 声明数 | 实际担任 |
|---|---|---|
| 12.5 | **55（62%）** | 正文、元信息、卡脚、图例、提示、按钮、出处——**六种角色一档** |
| 9 | 18（20%） | 英文品牌、`NO.0025`、`POEMS 1468`、"关系"、侧栏编号 |
| 17.5 | 5 | 主标题、卡内诗、右栏释义 |
| 23 | 5 | 卡内诗题、长诗正文 |
| 11 | 3 | 只有图例计数（`.lg .c`） |
| 15 | 1 | 只有点评页 `.crit .ct` |
| 34 / 66 | 1 / 1 | 全屏诗正文 / 全屏诗题 |

- 34px 在注释里是"章节标题"，实际是诗正文；23px 名义"诗题"，实际是长诗正文——**阶的名字和阶的岗位对不上**，以后再改就会又乱。
- 11px 和 15px 各只服务一个孤立元件，等于空转；真正的"正文—注文"二段差没有（12.5 一个人干完）。
- `var(--tN)` 只被引用 6/89 次，其余 83 处仍写死数字——这一轮的"收口"是 find-replace 收的，不是 token 收的，下一轮加两个元件就会重新长出 13px、15.5px。

## 四、竖排与行距：节奏对了，间距还太松

**诗卡竖排（1920）**：17.5px / `line-height:2` / 列距 16px / 字距 2.8px。

- 每字进给 **25.6px = 1.4629 × 字号**（含 2.8px 字距），七言列高 179px。
- 列宽 35px（`line-height:2` 撑出来的）+ 间隙 16 = **列轴距 51px = 2.91 × 字号**。竖排的中式排版，列轴距通常 1.8–2.2 倍；这里多出的 0.7–1.1 倍，直接换成"每屏少看 3 列"。
- 200 列：`scrollW=10,244 / clientW=451 = 22.7×`，可见 **8 列 = 4%**。这一轮加了提示与点击，**容器没动**——4% 仍然是 4%。
- 诗区 368px 里，列只占 128px（5 字诗）——**上下 240px 空着**，提示被推到最底下那一行，看起来像脚注而不是入口。

![长诗卡：8/200 列，诗墨 128px，240px 空带，提示在最下面一行](r4_type/05_card_long_1920.png)

**改法（连同上面的 fitPoem 一起落）**

```css
#card .poem{padding:22px 26px;gap:10px;align-items:flex-start}  /* 顶对齐，溢出可滚，不再两头切 */
#card .col{line-height:1.8;letter-spacing:.12em}               /* 列宽 31.5 → 列轴距 41.5 = 2.37× */
```

列轴距 51 → 41.5，同一 451px 里可见 **10–11 列**；顶对齐后，长诗的 128px 列块贴住诗区上沿，240px 空带消失，提示回到诗的正下方。

**全屏行距**：34px 配 2.2（74.8px）是海报密度，不是书；长诗 23px 配 1.9（43.7px）反而正好。上面第三节的 `1.8` 建议同时解决 1366 的溢出与 1920 的过松——**两档行距应当同源**，不要再让"短诗 2.2 / 长诗 1.9"各写各的。

**竖排本身没有坏**：`writing-mode:vertical-rl` + `text-orientation:upright` + `flex-direction:row-reverse` 保证首列在右、自右向左；200 列的顺序实测正确（绝塞乌蛮北 → 孤城白帝边 → …）。要动的只是间距与容器。

---

## 五、一句总评

这一轮交出的是一份**真正的字号系统**：89 处声明、8 个数、0 个越阶，默认屏从上一轮的 8 个字号收到 4 个；全屏短诗回到单栏居中，长诗三栏且右栏常驻；底栏压暗让右下提示的最坏对比度从 2.76 回到 3.56。字这一层终于有了秩序。

但它**只在 1920×1080 的秩序里成立**。到 1366×768——最常见的笔记本——诗卡每列上下各被切 13px、全屏最后两句掉出屏幕；长诗卡把诗缩成 4% 的一条，靠一行灰色的"点这里整屏读"来救；全屏换了诗却不重置滚动位置，读者从"犀箸厌饫久未下"这种半句开始，且不知道这是哪一首。**68 分：阶修好了，场还没修——而诗是要在"场"里读的。**
