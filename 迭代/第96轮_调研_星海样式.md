## A. 视觉：星海「显贵」的十一条硬规律

**A1 · 星等是长尾，不是均匀分布。** 肉眼星数按星等每档约 ×3.0–3.6（累计数：15→48→171→513→1602→4800→9100），亮度按 2.512^(−m) 衰减。
实现时用 `mag = mMax − ln(1−u)/ln(3.2)` 反解，就会自然长出一条「少数极亮、多数极暗」的尾巴。
来源：[Apparent magnitude](https://en.wikipedia.org/wiki/Apparent_magnitude)（该表是 1997 年估计，维基自己标了「需更新」；当**比例**用没问题，别当精确星表）。

**A2 · 亮星要「少而大」，两级就是全部秘密。** 100,000 Stars 源码：1% 的点尺寸再乘 `pow(1+r, 3+3r)*0.9`（0.9–57 倍），另 30% 乘 4–16%。
这比整体提亮有效得多——它造的是「天上那几颗扎眼的」，不是「整体发白」。

**A3 · 星点永远加色、永不写深度。** 三家一致：`AdditiveBlending + depthWrite:false + transparent + sizeAttenuation`。
加色让重叠处自然过曝成白核；写深度反而会把前后星切断。

**A4 · 点大小按距离衰减，夹在 0.55–4.2px。** 本项目 `sz = SZ*px*(2.6/d)` 与 100k 的 `200 + clamp(600/dist, 0, 32000)` 同构；
关键是**别让暗星小于 0.55px**，否则它们会消失、盘面变稀。

**A5 · 颜色 = 半径函数 + 每通道 ±0.1 抖动。** 100k 源码：`r=clamp(1−d³·2e−8, .3, 1)`、`g=clamp(.7−d²·1e−6, .41, 1)`、`b=clamp(.1+d·.004, .3, .6)`，再各加 `random(−.1,.1)`。
核心暖、外圈冷，抖动负责「不像是算出来的」。

**A6 · 色温可从 B−V 直接算。** Ballesteros 式 `T = 4600·(1/(0.92BV+1.7) + 1/(0.92BV+0.62))`；
对照点 42000 / 30000 / 9790 / 7300 / 5940 / 5150 / 3840 K（O→M），省事就直接用这七个色标插值。来源：[Color index](https://en.wikipedia.org/wiki/Color_index)。

**A7 · 尘埃做两层：一层刀口、一层糊。** 100k 给银道带备 `sharp` 与 `blur` 两张图，着色器 `blurDivisor 2.0`、`blurPower 1.0` 混合。
Canvas 2D 等价：同一路径画两遍——一遍 1px 硬边，一遍 8–12px 模糊、alpha 0.35。

**A8 · 泛光只有三个数：threshold 0 / strength 1 / radius 0.5。** 官方示例配 `ACESFilmicToneMapping`，曝光 `pow(v,4)`。
Canvas 2D 等价：把亮部抽到 1/4 分辨率、模糊 8–12px、`lighter` 叠 1–2 次，成本约全屏 1/16。来源：[UnrealBloom 示例](https://threejs.org/examples/#webgl_postprocessing_unreal_bloom)。

**A9 · 镜头要「呼吸」，但不能抖。** 100k 每次滚轮给相机塞 `±0.0001 rad` 随机旋转（按 z/1000 缩放）——人眼读作「手在动」，读不出「在抖」。
本项目 `autoSpin` 是 0.000045 rad/帧 ≈ 0.155°/s，同量级，可继续复用。

**A10 · 长焦比广角更「高级」。** 100k 用 **FOV 30°**；Celestia 默认 45°；SpaceEngine 默认 45°、缩放 20°。窄 FOV 压缩景深、让星点更密。

**A11 · 暗角 + 颗粒是最后一道胶片感。** 本项目暗角 0.46 已合适；颗粒取 2–4% 不透明度、每帧重随机的单像素噪点，
别用静态贴图（静态会被看成「脏」而不是「胶片」）。

## B. WASD 自由飞行：可直接抄的数值

**B1 · 键位照游戏惯例，别自创。** SpaceEngine：WASD 平移、R/F 升降、Q/E 滚转、按住左键环视。
Celestia：A/Z 加减速、Q 反向、S 停止、X「朝屏幕中心飞」。

**B2 · 速度用「档」不用「连续」。** Celestia 给离散预设 F2–F7：1 km/s → 1000 km/s → 1c → 10c → 1 AU/s → 1 ly/s，每档约 ×1000。
太空尺度下连续调速不可控；本项目建议 5 档 ×4：`0.25 / 1 / 4 / 16 / 64` 单位/秒。

**B3 · Shift 可以既是冲刺又是精修。** three.js FlyControls 里 Shift 反而把 `movementSpeedMultiplier` 设成 **0.1**（减速求解）。
本项目建议 Shift = ×4、Ctrl = ×0.25，两个都给——「看全盘」和「贴到某颗星」是两种速度。

**B4 · 惯性用一阶逼近，8 帧到位。** 100k 的 `z += (target−z)*0.125`（60fps 下约 0.13s 收敛）。
速度同理：`v += (vt−v)*0.12`，松键后 `v *= 0.90/帧`（半衰 ≈ 0.11s）。

**B5 · 环视灵敏度 0.002 rad/px 起步。** PointerLockControls 的 `_MOUSE_SENSITIVITY = 0.002`（再乘 `pointerSpeed=1.0`）；
100k 实测约 0.001745 rad/px（0.1°/px）。本项目取 **0.0022 rad/px（≈0.126°/px）** 最稳。

**B6 · 俯仰夹死，别让人翻过去。** 100k 允许 ±90°；游戏惯例留 5° 余量，建议 ±85°。

**B7 · 准星要极轻。** SpaceEngine 不画准星，靠「选中的天体」给朝向；建议 1px 十字 + 8px 空心环、alpha 0.35，
对准诗星时才升到金色——符合本项目「金只编码关系」的宪法。

**B8 · 读数放右下角，等宽、两行。** SpaceEngine 把「绑定天体 / 速度 / 实际速度」放左下，「限制星等 / 当前 FOV」放右下，全是 label + 数值的等宽小字。
本项目建议：`距离 3.9 · 速度 1.2 · FOV 89°`，11px，`font-variant-numeric: tabular-nums`。

**B9 · 自动巡航 = 慢到看不出在动。** 100k 的 tour 节奏是「飞 3–10s、停 3–6s、步间缓冲 1s」。
本项目待机 2.4s 后 0.155°/s 漂移已接近；可再加「双击空白 = 沿当前朝向匀速巡航」。

**B10 · 边界回弹，不要硬墙。** 软边界 1.15× 盘半径，越界后速度 ×(−0.35)、约 0.25s 拉回；2.2× 盘半径再硬夹。硬墙会让人瞬间失去方向感。

**B11 · 滚轮步进 5% 就够。** 100k 每格 **1%**（乘法）；本项目现在 0.925 / 1.08（7.5% / 8%）太猛，建议 0.95 / 1.05。

**B12 · 进出过渡沿用已有曲线。** DESIGN 定的 0.045 插值 ≈1.2s 用于场景切换；100k 内部微调用的是 0.125/帧（≈0.13s）。
两者别混——切「星海↔天球」用 1.2s，镜头微调用 0.13s。

## C. 文字排版

**C1 · 字号阶梯要有模数，现在缺 20。** 本项目 9/11/12.5/15/23/34/66 的相邻比是 1.22 / 1.14 / 1.20 / 1.53 / 1.48 / 1.94——
中间两跳几乎 ×1.5，其余 ×1.2。要么补 20 让 15→20→27→40 顺下来，要么把 23 降到 21、34 降到 32，向 1.5 靠。

**C2 · 行高：正文 120–145%，深底 1.65–1.8。** Butterick 的 120–145% 是纸面经验，深底要更松；
数据行反向收紧到 1.25–1.35，两行读数才像「仪表」不像「段落」。来源：[line-spacing](https://practicaltypography.com/line-spacing.html)。

**C3 · 行宽：西文 45–90 字符，中文 30–40 字。** 长诗阅读列按 30–34 字最稳（本项目 65–75 字符宽 ≈ 32 汉字，已经对）。
来源：[line-length](https://practicaltypography.com/line-length.html)。

**C4 · 字距随字号走，西文大写别学 logo。** 中文 9–11px 加 0.01em、15px 以上 0.02–0.03em；西文全大写常规 0.08–0.12em。
本项目 .34em 属 logo 级，只该出现在 9px 栏目标签上。

**C5 · 中西混排留 1/4 em，不超过。** W3C clreq：汉字与西文字母/数字之间，间距**不超过汉字宽度的四分之一**，行首行尾不加。
数字一律 `tabular-nums`，否则读数会跳。来源：[clreq §6.2](https://www.w3.org/TR/clreq/)。

**C6 · 双轨字体：正文衬线、数据等宽。** 100k 用 Lora（正文 14/20）+ Lekton（数据），对比清楚又不吵。
本项目对应「思源宋体正文 + ui-monospace 读数」，两轨之间不混用。

**C7 · 面板贴四角，安全边距 24px。** 顶部标题、左下状态、右下读数、右上模式切换；窄屏降到 16px；
面板内留白只有 12 / 16 / 24 三档，别再出现 13、17 这种手写值（与 DESIGN 的「八档字号」同一条纪律）。

**C8 · 一屏一个强调色，面积 ≤5%。** 100k 只用纯白 + 55% 白，连第二色都没有；本项目金 `#C9A227` 已限定「只编码关系」，
调研结论是**继续保持**，别为「更美」加色。

## D. 落到本项目：第 96 轮的可执行清单

**D1 · 视角放小，改一个数就够。** `cam.dist` 2.9 → **3.9**：盘面半径从 `0.477·min(W,H)` 降到 `0.355·min(W,H)`，整盘直径 95% → 71%，
四边各留约 15% 呼吸位（公式 `sc = min(W,H)*0.92*cam.zoom*cam.fov / dist`，盘半径 0.97）。

**D2 · 放小之后必须补亮度。** 尺寸项 `(2.6/d)` 在 d 从 2.9→3.9 时衰减到 0.74 倍，把系数改成 **3.5**（或 SZ 基数 ×1.34）抵消；
同时把 0.55px 下限抬到 **0.6px**，保住暗星，否则整盘会「变暗变稀」。

**D3 · WASD 最小改动点：给相机加位置。** 新增 `cam.px/py/pz`，投影改成 `sx = CX + (xr−cam.px)*sc`。
**关键坑**：`GALKEY`（第 1691 行）只记 yaw/pitch/dist/zoom，必须补三个位移字段，否则星海缓存永不重绘。天幕是球心视角，不受位移影响。

**D4 · 速度与阻尼：三行代码。** `vt = 档位*(Shift?4:1)`；`v += (vt−v)*0.12`；松键 `v *= 0.90`。
位移 `p += forward*v*dt`，`dt` 取 `Math.min(0.05, 实际间隔)`，防切标签页回来瞬移。

**D5 · 边界：软回弹 1.15R，硬夹 2.2R。** 越界时 `v *= −0.35` 并把位置拉回 1.15R 内，避免「飞出去满屏没有任何东西」。

**D6 · 排版三处最小改动。** ① 读数改 11px / 1.3 等宽 + `tabular-nums`；② 中文与数字之间 `margin:0 .25em`（只加行内，不加行首尾）；
③ 标题只保留 15 / 23 两档，不再加新字号。

**D7 · 风险登记。** 位移后 `pick()` 的屏幕坐标反查会失准（现在按 `cam.dist` 反投影），需把 `cam.px/py/pz` 一并进反投影，
否则「飞过去点不到星」。验收口径：1600×900 与 1440×900 各飞一次全程。
